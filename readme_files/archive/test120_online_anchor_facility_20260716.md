# Test120：在线锚路径设施反馈（已撤回）

更新时间：2026-07-16。Test120 尝试把 Test119 的锚路径设施上界从“每个 D 层结束时计算一次”前移到普通有序行完成事件。该实验正确，但没有产生足以覆盖额外调度复杂度的状态收益，源码、构建目标和输出字段均已撤出；本文件只保留负结果。

## 1. 假设

Test119 在 D2、D3 层末分别得到 `10.0181663554` 和 `9.9770319196`。如果相同上界在层内更早出现，后续 row closure 可能使用更小的 incumbent，从而少生成状态。最直接的每行重算会把 `O(3^(g-1))` 的 partition DP 乘上行数，在固定 `g=15` 小图上已经明显过慢，因此没有进入大图门禁。

随后实现了一个由工作量推导的 rent-or-buy 调度：累计新 row values 的顺序扫描工作，只有累计工作足以支付一次规范化 partition 枚举时才重算；层末仍强制计算一次。规则不读取数据集名、询问编号、固定层号、密度或 wall time，符合 `agent.md` 第六条，但它仍需要额外 credit、重复求值和调试统计，只有产生明确状态收益才值得保留。

## 3. 结论

Test120 说明当前瓶颈不是 Test119 上界晚了几十张 row，而是**上界本身在 D3 后仍不够强**。后续不再优化同一标量设施上界的反馈频率，应研究能够共享锚树连接或保留更多 rooted 结构的合法上界。
