# Test130：同时删除末层 D/A 的完备性反例

更新时间：2026-07-16。Test130 已从源码和 CMake 撤回，没有运行 Toronto 或 DBLP。

## 1. 假设

DBLP g15 q33 的历史日志把 A5/A6 的联合阶段 best 记为 exact，而 `D7` 与 `A6` 分别耗时 `1438.464s` 和 `1730.497s`。当时据此提出 Test130；后续 Test129 已确认该日志不能区分首次更新来源。Test130 检查的纯结构问题仍然成立：对 `h=floor(g/2)`，只生成普通状态到 `D_{h-1}`，锚状态只生成到 `A_{h-2}`，再用已有的 exact `A+D+D` 完成操作求解，是否仍然完备。

该探针只有编译期状态边界，没有数据集、固定 `g`、层密度、运行时刻或经验阈值。它保持 permanent-anchor A 递推、root-irreducible D branch、离线有序行、下界与完成操作不变。

## 2. 反例

Release/O2 随机对拍使用 DPBF 和 `1e-6` 精度。宽范围门 `seed=717511, g=5..15` 在第 18 例得到：

```text
g       10
DPBF    32
Test130 34
```

固定目标层门 `seed=717512, g=15` 在第 90 例得到：

```text
DPBF    50
Test130 51
```

固定 g15 反例在 `A2` 首次把 incumbent 从 `57` 降到 `51`，之后 `A3/A4/A5` 均不再改善；缺失的 `D7` 使现有完成族无法表示成本 `50` 的最优树。这不是浮点误差，也不是小 g 边界现象。

## 3. 结论

`A_{h-2}+D_{h-1}+D_{h-1}` 不是一般完备端点，不能通过同时删除最高 D/A 层把 q33 的两段时间直接省掉。Test130 本身不能判断只删除最终 A 层是否安全；后续 Test129 已用独立 7/4/4 decoy-tree 反例证明，即使保留 `D_h`，最终 A 层也不能删除，见 `test129_penultimate_a_completion_20260716.md`。

下一步若要消掉 `D_h`，状态必须补回反例中缺失的 paid attachment 或第二接口信息，而不能仅重新分配三个 block 的大小。本轮没有新增论文引用；DPBF 仅作为离线正确性核验器。
