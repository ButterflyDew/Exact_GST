# Test132：最终 A Consumer 的转置闭包

更新时间：2026-07-16。Test132 的 min-plus 恒等式和实现均通过正确性门，但固定跨询问面板端到端回退；源码、CMake 目标和临时输出已经撤回。它没有进入 Test80，也没有触发 DBLP q25、g15 q33 或全询问长跑。

## 1. 出发点

对一个最终 anchored mask `S`，记生产侧在根 `u` 的未闭包代价为 `F_S(u)`，补集侧两个普通分量在根 `v` 的未闭包代价为 `G_R(v)`，其中 `R` 是 `S` 的补集。原 Test80 先闭包生产侧，再与补集侧相交：

```text
min_v closure(F_S)(v) + G_R(v).
```

由于图是无向图，最短路距离满足对称性，交换两次最小化的顺序可得精确恒等式：

```text
min_v closure(F_S)(v) + G_R(v)
= min_u F_S(u) + closure(G_R)(u).
```

Test132 因而尝试反转最终 consumer 的闭包方向：不再生成完整最终 A row，而是先从补集侧构造临时 `G_R`，闭包 `G_R`，并在实际弹出的根上按需查询 `F_S`。这不是近似剪枝，也不改变永久锚 A、root-irreducible D branch 或最终目标值。

## 2. 实现细节

`G_R` 的种子继续使用 Test80 的规范 pivot 与 branch basis 枚举，而不是恢复完整的对称 D+D 分区。反向 Dijkstra 使用生产侧的可采纳势函数，取 directed-cut、锚组和 `S` 中各组到根距离、group-tour 下界的最大值；一个根出队后，才通过已有离线有序 A/D rows 点查 `F_S(u)`。实现没有 Hash、数据集判断、固定 `g`、层密度、运行时刻或经验阈值。

该方向在理论上与原方向完全等价，但两边工作量并不对称：原方向支付 `F_S` 的有序合并和闭包，转置方向支付 `G_R` 的种子生成、闭包及若干 `F_S` 点查。仅凭状态数无法预先保证哪一边更便宜。

## 3. 正确性门

Release/O2 以 DPBF、`1e-6` 为准，全部通过：

```text
wide g=4..15     seed 717544    200/200
fixed g=15       seed 717545    100/100
```

更早的实现阶段还通过 wide/fixed g15 共 `300` 例；这些结果只用于定位实现，不重复计入最终门禁。

## 4. 固定面板结果

fast20 中 Test80 合计 `7.220568s`，Test132 合计 `7.280025s`，回退 `0.82%`；逐实例为 `10` 胜 `10` 负，没有稳定方向。

## 5. 结论

Test132 证明了最终 consumer 可以精确转置，但没有证明转置方向在工作量上支配原方向。Toronto 五询问中只有 q4 端到端改善，合计回退；fast20 也正好一半胜负。若同时实现两个方向再按数据、层号或经验时间选择，会违反 `agent.md` 第六条；除非未来能从两侧已知行规模推出一个完备、无经验参数的成本支配判据，否则不恢复该分支。

本轮最重要的方法论结论是：**q1 或任一单条 q 都只能证明该询问。** 开发门禁应先看固定多询问面板的逐条配对与合计结果；论文若报告 DBLP g13 的总体性能，应运行全部询问，或预先声明与候选结果无关的分层抽样协议，并报告离散程度。本轮没有新增论文引用。
