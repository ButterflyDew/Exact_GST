# Test140：锚树设施方案的真实边并集

更新时间：2026-07-16。Test140 已从活动源码、CMake 目标和构建产物撤回。本轮检查 Test121 的标量设施方案是否因为重复计费而错过更强的 D2 后上界，并进一步尝试直接按边并集的边际代价选择 paid blocks。两种候选都是 permanent-anchor A 框架内的合法 primal upper，但固定 Toronto g13 q1--q5 面板只有 q1 减少后续状态；边际并集选择在五条询问上还全部弱于原加法方案，因此没有启动 DBLP。

## 1. 结构动机

Test121 在压缩锚树上选择若干 rooted D-block。它的目标函数把每个 block witness、所用锚树路径和 anchor path 分别相加。同一条原图边若同时出现在多个 witness 中，会被重复计费。Test140 在 D2 自然边界恢复真实边集合：singleton block 是设施节点到该组的一条最短路；D2 block 是两个组到 split root 的路径与 split root 到设施节点的传播路径；压缩锚树边则恢复为其对应的原图父树路径。所有边按原图 edge id 去重后再求和，全程不使用 Hash。

设 Test121 选择的组件边集为 `E_1,...,E_r`，其加法值为各组件路径长度之和。边并集 `E=union_i E_i` 仍与 anchor path 连通并命中所有组，因而是合法 GST；同时每条非负边至多从多次计费降为一次计费，所以：

```text
w(E) <= sum_i w(E_i) = U_tree.
```

因此方案恢复得到的 `U_plan-union` 始终是合法上界，且理论上支配 Test121 的同一方案。D2 是这里的结构边界：singleton 与 pair rooted state 都能从精确最短路/D2 递推恢复真实 witness；本轮没有按数据集、固定 g、时间、密度或经验层号切换策略。

## 2. 真正的并集目标

“先最小化加法值，再对唯一最优方案去重”仍可能选错方案。为直接利用已付边，本轮又枚举每个锚树节点上的 singleton/D2 witness，并把该 witness 到 anchor path 的锚树路径一并视为一个候选组件。从空的非锚覆盖开始，每轮选择：

```text
新增未付边代价 / 新覆盖组数
```

最小的组件，直到覆盖全部非锚组。该规则没有阈值或宽度参数；每次加入的组件都已连接到 anchor path，所以任意中间结果及最终边并集都保持可行。它只是 primal upper，不参与正确性所需的状态删除证明。

## 3. 正确性门

Release/O2 黑盒 DPBF 对拍全部通过：宽范围 `g=2--8` 使用 seed `718003`，结果 `100/100`；固定 `g=15` 使用 seed `718004`，结果 `30/30`。此前只恢复 Test121 方案的版本还通过 seed `718001/718002` 的同规模 `100+30` 例。所有误差均不超过 `1e-6`。

## 5. 否决边界

Test140 说明，**重复计费确实存在，但不是 Test121 跨询问瓶颈的主要来源**。它只恢复锚树几十个设施节点上的 D2 witness；Test127 已证明更强的 paid geometry 大量位于这些节点之外，而把任意 D2 根仅压成“最近 attachment site + 一个距离”又缺少第二接口。继续扩大固定 site 数、设置 skyline 宽度或按询问挑根会违反当前研究纪律，也不会补上完备性。

保留的理论信息有两点：一是任意标量 facility 方案都可无损恢复为真实边并集上界；二是若未来状态显式保存 paid subtree，目标必须保留多个 attachment 对后续 block 的相关性，不能先独立选 block/root 再期望事后去重修复。下一步应回到受控多接口 profile 或能够批量生成该 profile 的 exact recurrence，而不是继续调锚树设施候选。

本轮没有新增论文引用，也没有运行 DBLP 探针或完整长跑。
