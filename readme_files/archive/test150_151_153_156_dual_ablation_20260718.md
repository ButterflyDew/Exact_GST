# Test150--151 / Test153--156：Dual 调度与代码简化归档

本文冻结 2026-07-18 为形成 Test152 而执行的诊断与消融。这里的版本均不是当前算法入口；活动结论见 `../test152_progressive_dual.md`。

## 1. Test150：完整 No-Dual 诊断

Test150 在完整求解器中关闭 sequential dual，其余状态流程保持不变。它不是候选方法，只用于归因 V5 小 `g` 的固定成本。

- eager dual 在三张 GPU4GST 小图的 `g=4` 求解时间中占约 `40%--54%`；
- no-dual 的 `g=4` 只比 Strict PrunedDP++ 慢约 `11%--25%`；
- `g=5` 起在已测低 `g` 面板上不再慢于 Strict，但不能据此删除大 `g` 所需的 dual 剪枝。

证据目录：`result_snapshot/v5_small_g_profile/20260718_test150_no_dual`。完整 no-dual CMake 目标已删除；仓库仍有较早 D2 profiling 目标，不作为运行策略。

## 2. Test151：一次性延迟购买

Test151 先以零 dual 执行普通行，累计

\[
N_{seed}+N_{pop}+N_{relax}.
\]

累计值达到完整 dual 的结构预算 `g(2m+n)` 后，再一次性构造全部组。规则没有数据集或固定 `g` 特判，且 `420/420` 条查询与 V5 权重一致；但高 `g` 通常比 V5 慢 `20%--30%`。原因是触发前的弱下界搜索已经发生，触发后仍要支付完整 dual，两个成本直接相加。

结论：完整 dual 不是合适的不可分购买单位。Test151 的源码分支、宏和 CMake 目标已删除，证据保留在：

- `result_snapshot/v5_lazy_dual/20260718_test151_g4_g8_q20`
- `result_snapshot/v5_lazy_dual/20260718_test151_g9_g10_q20`

## 3. Test153--155：重模块删除消融

Test153 同时删除 junction 与 anchor facilities。低 `g` 最多改善约 `11%`，但高 `g` q1--q5 面板可慢到 Test152 的 `1.98x`，因此不能为了源码短而整体删除。

Test154 同时删除 early 与 quarter partition uppers，高 `g` 为 Test152 的 `1.02x--1.22x`。该结果只能说明二者合计有用，不能说明 quarter 单独有用。

Test155 保留 junction、删除 facilities/tree，普通短面板约为 Test152 的 `0.99x--1.07x`；但既有重查询证据显示 facilities/tree 可减少约 `4%--22%` 状态和 `7%--14%` wall。其调用已经由实际 ordinary 工作摊销，不再对轻查询无条件执行，因此保留。

packing 在高 `g` 30 条查询中有 `16` 条产生非零增强，也予以保留。

证据目录：

- `result_snapshot/v5_simplification_ablation/20260718_test153_test154`
- `result_snapshot/v5_simplification_ablation/20260718_test155_no_anchor_facilities`
- `result_snapshot/v5_simplification_ablation/20260718_test152_upper_stats`

## 4. Test156：Quarter Upper 单独消融

在 30 条高 `g` q1--q5 查询中，quarter upper 只有两条更新：Twitch g8 q1 将 incumbent `545 -> 540`，Github g8 q1 将 `852 -> 765`；后续 witness 又分别改进到 `511` 和 `673`。两次 quarter 调用耗时 `11.799ms/19.640ms`，但端到端均约慢 `18ms`，状态减少也很小。no-quarter 面板相对 Test152 的比例为：Musae g8/g10 `1.00/1.02`，Twitch `0.95/1.00`，Github `1.06/0.96`，没有稳定收益。

结论：quarter upper 是本轮确认的无效复杂优化。相关实现、统计字段、编译开关和临时目标均已物理删除；Test21 中同名的旧研究统计属于另一方法，没有混删。证据目录：`result_snapshot/v5_simplification_ablation/20260718_test156_no_quarter`。

## 5. 归档纪律

Test150、Test151 和 Test153--156 的二进制入口不再维护。结果只用于解释 Test152 的形成与源码去留，不能写成当前方法的独立性能版本，也不触发 DBLP g13 全量重跑。
