# Test81：D2-Junction 局部分块归档

更新时间：2026-07-14。本轮尝试把 Test80 已生成的精确普通 pair 行接回 branch-junction 压缩树，希望在 D2 结束时前移原本到 D4 才出现的强 incumbent。机制通过正确性与快速测试，但 DBLP g13 的两个 D2 前缀压力样本只得到约 `1.3%` 的上界改善，远未复现 D4 的降幅。因此源码、公共 API、统计字段、探针目标和临时结果均已撤出；本文只保留可复核结论。

## 1. 动机

19 条 DBLP g13 跨询问记录显示，重询问通常要到 D4 才第一次显著降低上界。以 q21 为例，junction 后为 `12.5030458400`，D3 后仍相同，D4 后才降到 `10.6970632464`；此时 D3/D4 行已经占约 `6.88GiB`。q25 同样从 `13.2946300967` 到 D3 的 `13.1536735692`，再由 D4 降到 `12.2807325738`，而 D3/D4 行合计约 `9.23GiB`。因此候选机制必须在 D3 之前产生实质上接近 D4 的可行解，才可能改变时间和空间主项。

## 2. 候选机制

初始 branch-junction 已构造一棵以 paid anchor path 为 super-root 的压缩父树。原实现允许树节点 `x` 用同根 star 服务任意组集合，局部代价是各组 `gd_i(x)` 之和。本轮在全部 D2 行完成后，对每个压缩树节点和每个 nonanchor pair 只查询一次精确值 `D({i,j},x)`，再做 singleton/pair 局部分块：

```text
L_x(empty) = 0
L_x(M) = min(
    L_x(M-{i}) + gd_i(x),
    min_{j in M-{i}} L_x(M-{i,j}) + D({i,j},x)
)
```

其中 `i` 固定为 `M` 的最低位，避免重复枚举同一分块。随后用原 junction tree convolution 合并各子树。每个局部项都是包含节点 `x` 的真实 rooted tree，父树边与 anchor path 也都真实付费；不同局部树即使共享边，代价求和只会重复付费，不会低估。因此所得值始终是一棵合法可行树的上界。缺失的 D2 root 只是不参与局部分块，singleton 仍保证可行。

该机制不改变 D/A 状态定义、完备性、lower bound 或执行框架，不使用 Hash、数据集名、固定 `g`、层号、密度、wall time 或经验参数。额外复杂度为 `O(|C'| k 2^k + |C'|3^k)` 时间和 `O(|C'|2^k)` 临时空间；每个树节点只做 `C(k,2)` 次 D2 lookup。

## 3. 正确性与 Fast20

Release/O2 随机对拍全部通过：

```text
seed 714201, g=2..13   200/200
seed 714203, fixed g13 100/100
```

fast20 中有 `7/20` 条在 D2 结束后改善 incumbent，局部 DP 累计 `114.32ms`。相对冻结 Test80 快照，普通状态总量由 `2,899,492` 降到 `2,798,634`，减少 `3.48%`；A 状态只由 `1,250,907` 降到 `1,247,670`，减少 `0.26%`。候选总查询时间为 `9.380s`，旧 Test80 为 `9.099s`；两轮还跨越了逐询问 RSS 采样改动，所以不把这 `0.281s` 差值解释为纯算法开销，但状态量已经表明收益远非数量级变化。

## 4. DBLP g13 D2 前缀

为避免重复 30 分钟至 2 小时的后续阶段，临时研究工具在完整 D2 层和局部 junction DP 后自然退出，不进入 D3、D4 或 A，也不写正式 `weights.txt`。

| query | junction | D2-junction | 历史 D4 后 | D2 values | local DP | D2 prefix wall |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| q21 | `12.5030458400` | `12.3388664487` | `10.6970632464` | `109,550,587` | `14.607ms` | `289.944s` |
| q25 | `13.2946300967` | `13.1126232870` | `12.2807325738` | `134,405,987` | `18.544ms` | `362.157s` |

q21 查询 `594` 个 pair/node 值，q25 查询 `792` 个，全部命中。换言之，失败不是 D2 root 被 incumbent 剪掉，也不是 lookup 成本过高；固定压缩树上的局部 pair 信息本身就不足。q21 与 q25 的改善分别只有约 `1.31%` 和 `1.37%`，而且仍明显高于历史 D4 后上界，因此没有触发任何完整 DBLP 运行。

## 5. 结论

本轮证明了精确 D2 可以低成本嵌入 junction tree 的局部 facility，但也给出了清晰否决：**把更精确的局部 block cost 填进同一棵固定 skeleton，不能替代 D4 暴露的更高阶 attachment geometry。** 继续增加 pair lookup、重复同一 tree DP 或因其毫秒级开销而保留代码，只会优化常数并扩张主线。

下一候选仍必须改变以下至少一项：在 D2 前构造具有覆盖性的新 skeleton family；让 skeleton 同时表示高阶 block 的第二边界；或让 lower-bound-aware ordered join 在候选物化前批量排除状态。固定 tree 上增加更多局部标量不再进入 Test80。
