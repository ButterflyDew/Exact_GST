# Test82：对偶行证书的整次合并剪枝

更新日期：2026-07-14。Test82 研究如何把 Test80 中“候选生成后才由 directed-cut 下界拒绝”的工作前移到离线有序行连接之前。该机制不使用 Hash、数据集特判、固定 `g` 特判或经验阈值；实验后因不降低状态空间且实际时间退化而完整撤回，当前 Test80 与 ReleaseV4 均未启用。

## 1. 动机与第一轮信号

对覆盖组集 (S) 的普通行记为 (D(S,v))，对偶势记为 φ。定义约化代价 ρ_S(v)=D(S,v)-φ_S(v)。若两行 (X,Y) 在同一根 (v) 合并，剩余组由 directed-cut 势补全，则候选的完整下界为

\[
\rho_X(v)+\rho_Y(v)+\phi_U(v).
\]

只读诊断在 fast20 上统计：单侧最小约化代价能够提前解释原逐候选对偶拒绝的 `55.81%`（D）和 `49.25%`（A）。这个数字只说明下界有相关性，**不等于能够省去同根相交或线性归并扫描**。

## 2. 整行证书

每个 D/A 行只附加两个标量：

- (r_X=\min_v \rho_X(v))，该行的最小约化代价；
- (c_X=\min_v(\rho_X(v)+\phi_U(v)))，该行的最小完整对偶代价。

对任意同根候选都有

\[
\rho_X(v)+\rho_Y(v)+\phi_U(v)\ge
\max\{c_X+r_Y,\ r_X+c_Y\}.
\]

因此，当右侧严格大于当前 incumbent 时，可以在进入有序行连接前跳过整对行。该结论同样适用于锚点行 (A(X,v)) 与普通行 (D(Y,v)) 的合并。实现保留原有按顶点排序的行，不增加逐顶点 Hash 或第二套索引。

## 3. 实际结果

Release/O2 fast20 中，证书跳过 `68,937` 次 D 行合并和 `35,434` 次 A 行合并，但 D 保留值仍为 `2,899,492`，与 Test80 完全相同；A 保留值也只出现浮点执行路径导致的极小波动。总查询时间由 Test80 的 `9.099s` 增至 `9.734s`，最大片上峰值由 `183.734MiB` 增至 `184.578MiB`。

为避免只凭低维快照否决，又执行了真实 Toronto `g=13` q1：ReleaseV4 为 `8.640760s / 58.547MiB / 0.7048467020`，证书版本为 `10.309701s / 59.449MiB / 0.7048467020`，时间退化约 `19.3%`。

## 4. 结论

整行证书是正确、无参数且保持离线有序列表的前置下界，但它跳过的主要是**原本就会被逐候选下界拒绝的工作**，没有减少 D3/D4 或 A4/A5 的保留状态。证书构造、packing 后刷新和额外分支的成本高于连接节省，因此不进入主线，也不触发完整 DBLP g13 长跑。

后续若继续研究“下界进入有序连接”，必须让下界产生可跳过的连续顶点区间、减少行物化，或改变消费者需要的状态集合；仅把逐点拒绝聚合成行级标量不再重复。
