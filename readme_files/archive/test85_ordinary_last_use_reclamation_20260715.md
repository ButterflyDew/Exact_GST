# Test85：普通行的最终消费者回收

更新时间：2026-07-15。Test85 尝试在 Test84 的最终 A 层执行期间，按可证明的最后消费者释放普通 `D(P)` 行。机制通过随机正确性验证，也降低了联合 D+A row payload；但 fast20 时间回退，真实 Toronto g13 q1 的空间收益很小，因此实现、统计字段和候选快照均已撤回，未运行 DBLP。

## 1. 最终消费者公式

记 nonanchor 全集大小为 `n=g-1`，最终锚定 mask 大小为 `f=floor(g/2)-1`。进入最终 A 层前，所有低层 A 与普通 D 已经完成。对于非 singleton 普通行 `D(P)`，后续只剩两类读取：

1. `P subset F` 时，`D(P)` 参与最终状态 `A(F)` 的 A+D 转移；
2. `P cap F=empty` 且剩余另一侧大小不超过 half 时，`D(P)` 参与 `A(F)` 的剩余容量完整化。

因此，令 `p=|P|`，其最终消费者数可以精确写为

```text
C(n-p, f-p) + C(n-p, f),
```

其中不满足大小条件的项取零。实现为每个已发布 D 行维护该计数；每个最终 A mask 完成转移和完整化后扣除对应消费者，归零即释放 `vertices/distances/branch_bits`。该规则没有数据集、固定 `g`、密度或 wall-time 特判，也不使用 Hash。

## 2. 正确性

计数覆盖 D 行在最终 A 阶段的全部两类读取。低层 A 已结束，最终层之后算法直接返回，所以计数归零等价于该 D 行在状态依赖 DAG 中已经完成最后一次使用。释放不改变状态值、执行顺序、上下界或候选集合。

Release/O2 随机图与 DPBF 对拍为 `100/100`，seed `714311`，范围 `n=4..18, g=2..13`。fast20 与 Toronto 的答案及 D/A values、pops 也与 Test84 完全相同。

## 4. Toronto g13 q1

两次候选 wall 为 `8.786478s/8.966212s`，答案均为 `0.7048467020`；Test84 单次为 `7.548647s`，Test83 三次中位数为 `8.296s`。候选把联合 row payload 从 `30,892,140B` 降到 `30,065,904B`，仅下降 `2.675%`；query peak 为 `57.176/57.250MiB`，Test84 为 `57.590MiB`。

普通阶段本身存在运行波动，不能把全部时间差都归因于回收；但两次真实运行均未显示时间正向，空间收益也不足以覆盖这种风险。

## 5. 结论

最后消费者公式是正确且可复用的生命周期结论，但在当前生产者顺序下，D3/D4 的最后消费者仍接近 A5 尾部。它只能回收已经越过峰值的大量行，无法像理想的层级流水线那样显著降低 process peak。q25 可能因 D/A payload 更大而受益，但本轮没有实际运行，不能用外推替代证据。

因此 Test85 完整撤回，Test80 回到 Test84。若以后重新使用该定理，前提应是新的状态调度能把 D3/D4 的最后消费者结构性前移，或 row storage 改成可批量回收的块式所有权；不继续微调逐 vector 释放常数。

Test85 没有新增论文引用；D/A 状态背景沿用 Test80 文档。该生命周期公式是仓库内推导，尚不宣称论文级原创性。
