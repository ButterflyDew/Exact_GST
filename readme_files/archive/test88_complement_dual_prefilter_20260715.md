# Test88：补集 Directed-Cut 预筛选（已撤回）

更新时间：2026-07-15。Test88 尝试继续降低 Test87 中 directed-cut 的逐状态求和成本。最终实现正确，但 fast20 明确退化、大图收益仅处于噪声量级且增加常驻内存，故代码、接口、统计字段、临时快照和 DBLP gate 均已撤出。

## 1. 候选机制

设 `phi_i(v)>=0` 是顶点 `v` 对组 `i` 的 directed-cut potential，当前剩余组为 `R`，已覆盖组为 `E`。数学上可把

```text
C_R(v) = sum(i in R) phi_i(v)
```

改写为“全组总和减去补集”。当 `E` 比 `R` 小时，若预存每个顶点的全组总和，补集表达式可能少读若干 group rows。实现仅在符号操作数满足 `2|E|+1<|R|` 时尝试该预筛选；这是直接的操作数比较，不是数据集或时间阈值。

浮点减法可能把理论相等值向上舍入，因此最终版本使用保守定向舍入得到不超过数学值的预筛选下界。若该值已经满足 `d+lower>best`，可安全拒绝；否则必须再调用原 `dual.At(v,R)`，恢复原来的逐位顺序精确值，然后继续 Test87。这样幸存候选的队列键和状态与 Test87 完全一致。

## 2. 验证过程

直接用补集值替换原 cut 的早期版本会因浮点求和顺序变化而改变临界剪枝及状态数，已立即否决。最终“保守预筛选 + 原 cut 回退”版本通过 seed `715221` 的随机 `100/100` 与 seed `715231` 的 `50/50`，fast20 的答案及 D/A values、pops 全部与 Test87 相同。

## 3. 否决数据

最终版本 fast20 wall 约为 `8.606s`，相对 Test87 的 `8.368112s` 退化约 `2.8%`。DBLP g13 q5 wall 为 `186.099s`，只比 Test87 的 `186.896s` 低约 `0.43%`，但 peak RSS 从 `2134.043MiB` 增到 `2153.355MiB`。一次大图的亚百分比变化不足以覆盖短套件稳定退化和约 `19.3MiB` 的额外数组。

该机制没有减少状态、连接或渐进工作，只是在两种 cut 求值之间增加了额外内存与分支。结论是：**用全组总和做补集预筛选不适合作为 Test80 主线。** 三个失败 fast 快照、q5 gate、随机目录和所有源码残留均已清理；有效的 Test87 gate 保留。
