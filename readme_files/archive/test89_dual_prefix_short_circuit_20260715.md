# Test89：Directed-Cut 同序前缀短路（已撤回）

更新时间：2026-07-15。Test89 尝试在 Test87 的 directed-cut 求和内部继续短路。机制不改变状态和浮点最终值，但 fast20 与 DBLP g13 q5 均退化，代码、公共 API、统计字段和临时结果已撤出。

## 1. 候选机制与正确性

原 `dual.At(v,R)` 按组 bit 从低到高累加非负 potential：

```text
C_k(v) = phi_1(v) + ... + phi_k(v).
```

在同一 IEEE double 累加顺序中，加入非负项不会让浮点和下降，所以任意前缀 `C_k` 都不大于最终 `C_R`。若候选代价 `d` 在某个前缀已经满足 `d+C_k>best`，完整 directed-cut 也必然拒绝，可以停止读取后续组。

实现把已处理项数与部分和缓存在 Test87 现有的 1-byte stage 和 `heuristic` 数组中。同一顶点以后出现更小的候选代价时，从原 bit 顺序继续；若走到末尾，得到的 double 与旧 `dual.At` 逐项相同。因此无需补集数组、向下舍入、第二次求和或 Hash。该结论在实现层面是严格的，不是经验近似。

## 2. Fast20 门槛

Release/O2 随机 seed `715301` 为 `100/100`，fast20 的权重、D/A values、pops 与 completion checks 均和 Test87 完全一致。首版逐次写诊断计数时 wall 为 `9.062s`；把计数改为每个 mask 汇总一次后为 `8.689s`，仍比 Test87 的 `8.368112s` 慢约 `3.8%`。

结构计数一度看起来有希望：D 实际读取 `81,624,031/123,751,929=65.96%` 的 potential terms，A 为 `39,116,525/57,252,015=68.32%`。这说明小图上能较早跨过阈值，但逐项条件分支仍比缓存内读取更贵。由于大图可能受内存工作集主导，该信号足以触发一次三分钟级 q5 gate，但不触发五小时 q1。

## 3. DBLP g13 q5 否决

| 指标 | Test87 | Test89 | 变化 |
| --- | ---: | ---: | ---: |
| wall | `186.895733s` | `202.975058s` | `+8.60%` |
| ordinary D | `97.984235s` | `111.067698s` | `+13.35%` |
| anchored A | `35.212340s` | `40.106885s` | `+13.90%` |
| completion | `2.440190s` | `2.316257s` | 波动 |
| peak RSS | `2134.043MiB` | `2134.340MiB` | 基本相同 |
| 最优值 | `14.5867185184` | `14.5867185184` | 相同 |

D/A values、pops 与 completion checks 逐项相同。与 fast 不同，q5 的前缀往往接近完整和才跨过阈值：D 读取 `3,067,579,858/3,404,570,123=90.10%` 的 terms，A 读取 `1,140,710,438/1,254,023,027=90.96%`。为了少读约 9% 的 group rows，算法在其余约 42 亿项后都执行一次加法后的条件分支，最终显著变慢。

## 4. 结论

**同序前缀是合法且数值等价的短路，但在当前 directed-cut 分布上不划算。** 按 dual 构造顺序重排可能更早命中，却会让幸存者重复读取原 bit 顺序或改变旧浮点和；Test88 已给出相关额外数组/回退的负证据。因此不继续围绕组顺序调常数。

撤回后纯 Test87 重新通过 Release/O2 构建及 seed `715302` 的随机 `50/50`。本轮没有新增论文引用，也没有运行 DBLP g13 q1。
