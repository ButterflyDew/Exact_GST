# Test92：逐 Label 的 A0 上界反馈（已否决）

更新时间：2026-07-15。Test92 以 Test90 为基线，尝试把最高普通层中的 A0 completion 从“row 完成后”进一步提前到每个 seed 或 relax label 通过现有下界检查之后。该改动已完整撤回，当前 Test80 仍是 Test90。

## 1. 思路与正确性

对正在构造的最高层 `D_h(S, v)`，其补集 row 已经完成。一个通过下界检查的 seed 是两棵更小普通子树在根 `v` 的并；一个通过下界检查的 relax label 是该子树再接一条图边。二者都对应可行的部分树。因此，只要补集 row 在同一根 `v` 有值，把当前 label、补集值和 anchor 到 `v` 的距离按原数值顺序相加，就得到合法全解上界。

被原下界拒绝的 label 无需检查。设其当前代价为 `d`，原下界为 `H`；补集 row 加 anchor 是一种具体完成方式，其代价不小于 `H`。若 `d+H>best`，这次具体 completion 也不可能改善 `best`。所以 Test92 不漏掉可能改善上界的 label，也不会错误剪枝。

实现不建 Hash：singleton 补集直接读取 group-distance，dense row 直接寻址，sparse row 在有序顶点数组中二分。每个被接受的 label 最多增加一次查找，最坏渐进空间不变。

## 2. 验证与否决

Release/O2 黑盒对拍通过宽范围随机 `200/200`（seed `715501`）和固定 g13 `50/50`（seed `715502`）。fast20 与 Test90 `result_snapshot/fast/20260715_015858` 对比：

| 指标 | Test90 | Test92 | 变化 |
| --- | ---: | ---: | ---: |
| solver 总时间 | `8.261585s` | `8.420050s` | `+1.92%` |
| 顶层 D values | `426,848` | `426,750` | `-98` |
| 顶层 D pops | `680,409` | `680,308` | `-101` |
| 在线补集查找 | `0` | `710,011` | 新增 |
| 成功共同根检查 | `82,797` | `153,359` | `+70,562` |

只有 3 个 fast 查询减少了顶层状态，绝大多数查询完全不变；`710,011` 次分散查找只换来 `101` 次 pop 减少。该粒度破坏了 Test90 的批量有序归并优势，并在跨库总体上稳定亏损，因此没有运行 Toronto g13 或 DBLP。后续若继续提前 A0 上界，只应利用 seed 结束、row 结束等算法自然边界做批量有序相交，不能引入经验批大小。
