# 方法：基于永久锚点与有序状态行的精确 Group Steiner Tree 求解

## 1. 问题定义与设计目标

给定一个带非负边权的无向图 `G=(V,E,w)`，以及 `g` 个终端组 `T_1,T_2,...,T_g`，Group Steiner Tree（GST）要求寻找一个最小权连通子图，使其至少包含每个终端组中的一个顶点。记 `n=|V|`、`m=|E|`，目标可写为

```text
minimize    sum(e in E(H)) w(e)
subject to  H connected
            V(H) intersects T_i for every i in {1,...,g}.
```

经典的精确方法通常以“已覆盖的终端组集合”和“当前根顶点”为状态。对固定组子集，所有根顶点上的状态值合称一张状态行；从若干同根合并候选出发，通过最短路传播得到所有根最优值的过程称为图闭包。若直接维护所有 `2^g` 个组子集与所有图顶点的组合，主要代价并不只来自子集数量，还来自三个更具体的问题：同一个子集需要反复执行图闭包；大量状态会在不同子集分割中被重复读取；只有在搜索后期才得到较好的完整解上界，导致早期状态难以剪除。

本文方法的核心思想是固定一个永久锚点组，将所有部分解分为“尚未接入锚点的普通部分”和“已经包含锚点的主干部分”。这种划分为每棵完整解指定了唯一的锚定侧，使普通部分可以作为可复用分支离线生成，而锚定侧只沿一条主线逐步吸收这些分支。在此基础上，方法使用更强的可行解上界和剩余成本下界，在每张状态行的图闭包过程中提前删除不可能进入最优解的根状态。

## 2. 方法概览

### 2.1 永久锚点分解

首先选择一个终端组 `T_a` 作为永久锚点组。令 `K={1,...,g}\{a}` 表示其余 `k=g-1` 个组，并令 `h=floor(g/2)`。本文维护两类精确状态：

```text
D(S,v): 连接所有 S subset K，并以 v 为根的最小普通树；
A(S,v): 连接锚点组 T_a 和所有 S subset K，并以 v 为根的最小锚定树。
```

普通状态只计算 `1<=|S|<=h`，锚定状态只计算 `0<=|S|<=h-1`。其中 `A(empty,v)` 等于顶点 `v` 到锚点组的最短距离，不需要显式存储。

这里的 A 状态不是在传统半层动态规划之外增加一套额外状态。传统方法中，大小不超过 `h` 的组子集可按“是否包含锚点组”分成两部分：不包含锚点的子集对应 D，包含锚点的子集去掉锚点后对应 A。由 Pascal 恒等式可得

```text
sum(i=1..h) C(g,i)
= sum(i=1..h) C(g-1,i) + sum(i=0..h-1) C(g-1,i).
```

因此 D 与 A 的划分不增加半层组子集的总数；它改变的是状态的组织方式和后续转移接口。

### 2.2 总体流程

整个算法依次执行以下阶段：

1. 对每个终端组计算到所有顶点的最短距离，并据此建立初始可行解上界；
2. 选择永久锚点组，构造用于剪枝的剩余成本下界；
3. 围绕一条根到锚点的最短路径构造共享汇合上界，在大规模状态展开前降低当前最优可行值；
4. 按组子集大小递增生成普通状态 D，并只向后续状态发布不可继续在当前根拆分的普通分支；
5. 在普通状态生成过程中，用已经完成的小块状态构造阶段性可行解，并在实际工作足够大时加强下界；
6. 按组子集大小递增生成锚定状态 A，每完成一张 A 状态行就与至多两个普通状态合并，更新完整解；
7. 当所有规定大小的 A 状态都完成后，当前最优可行值即为精确最优值。

下面按照这一顺序介绍各阶段。

## 3. 组距离、初始上界与剩余成本下界

### 3.1 组距离与共同根上界

对每个终端组 `T_i` 执行一次多源 Dijkstra，得到

```text
d_i(v) = min(t in T_i) dist_G(v,t).
```

若选择顶点 `v` 作为共同根，并分别沿最短路连接每个终端组，则得到一个合法连通方案，其成本不超过

```text
U_star(v) = sum(i=1..g) d_i(v).
```

算法选择 `r=argmin_v U_star(v)`，并以 `B=U_star(r)` 初始化当前最优可行值。这里及下文中，`B` 始终表示某个真实可行解的成本上界。

永久锚点组选择为在根 `r` 上距离最远的组：

```text
a = argmax_i d_i(r).
```

该选择使根到锚点的已付费路径尽可能承担后续组的公共接入。锚点一经选择便保持不变，算法不会枚举多个锚点，也不会根据数据集或运行时间切换锚点。

### 3.2 基于组间路径的下界

定义两个终端组之间的距离

```text
delta(i,j) = min(u in T_i, v in T_j) dist_G(u,v).
```

对任意尚未覆盖的组集合 `R`，在该组间度量上用 Held--Karp 动态规划计算覆盖 `R`、端点为 `i,j` 的最短 Hamiltonian path 长度 `HP(R,i,j)`。从根 `v` 出发连接 `R` 的任意树，边加倍后可以形成一条遍历所有命中组的闭合游走，因此

```text
H_tour(v,R)
= 1/2 * min(i,j in R) [d_i(v) + HP(R,i,j) + d_j(v)]
```

是合法的剩余成本下界。

### 3.3 基于边容量分配的下界

组间路径下界只使用终端组之间的距离，没有区分不同组的连接路径能否共享图边。边容量下界进一步观察原图中的每一条边，并把它理解为一份**最多只能收取一次的费用预算**。算法把每条无向边 `{u,v}` 临时看成两个记账方向 `(u,v)` 与 `(v,u)`，两个方向的初始容量都为原边权 `w(u,v)`。这只是下界证明中的记账方式，**不会把原图改成有向图，也不会让可行解重复支付一条无向边**。

对每个终端组 `T_i`，算法维护一个顶点势函数 `pi_i(v)`。直观上，`pi_i(v)` 表示从 `v` 出发，为最终连接到组 `i` 至少预留的那部分费用。势函数需要满足两个条件：

1. 对任意终端 `t in T_i`，有 `pi_i(t)=0`，因为到达该组后不再需要为组 `i` 支付剩余费用；
2. 对每条有向记账弧 `(u,v)`，所有组在这个方向上的正势差总和不能超过原边费用：

```text
sum_i max(0, pi_i(u)-pi_i(v)) <= w(u,v).
```

第二个条件是整个下界的核心。若从根沿边 `(u,v)` 向终端方向移动，组 `i` 的势最多下降 `max(0,pi_i(u)-pi_i(v))`；可以把这一下降理解为组 `i` 向该边收取的费用。约束保证：**即使多个组的根到终端路径共享这条边，它们在该边上的总收费也不超过边权**。

例如，一条权重为 5 的主干边同时服务两个组。势函数可以让两个组在该方向上分别下降 2 和 3，此时总收费正好为 5；不能让二者分别下降 4 和 4，因为总和 8 会违反容量约束。于是最终计算 `pi_1(x)+pi_2(x)` 时，两个组都能贡献下界，但这条共享边合计仍只贡献至多 5，而不是被完整计算两次。

现在考虑一棵以 `x` 为根、连接尚未覆盖组集合 `R` 的任意树。为每个 `i in R` 选择树中一条从 `x` 到 `T_i` 的路径，并把树边统一按远离根的方向定向。沿组 `i` 的路径累加势差，由 `pi_i(t)=0` 可知，这条路径上的正势差之和至少为 `pi_i(x)`。另一方面，同一棵根树中的每条边对所有组路径都具有相同的根向外方向，因此可用上面的逐弧容量约束把该边的所有收费合并，并且最多计一次 `w(e)`。对所有组和所有树边求和得到

```text
H_cut(v,R) = sum(i in R) pi_i(v).
```

所以 `H_cut(x,R)` 不会超过任何从 `x` 连接 `R` 的真实树成本，是合法的剩余成本下界。这里最容易混淆的一点是：公式虽然把各组的势相加，但**逐边容量约束已经消除了共享边的重复收费**。

初始势函数按以下过程构造。令 `c_res(u,v)` 为当前尚未分配的有向容量，初始为 `w(u,v)`。算法按各组在共同根 `r` 上的距离由远到近处理。处理组 `i` 时，在剩余容量图上计算到 `T_i` 的有向最短距离 `d_i^res(v)`，并以根处距离截断：

```text
C_i = d_i^res(r),
pi_i(v) = min(d_i^res(v), C_i).
```

最短距离保证每条弧上的正差不超过该弧当前剩余容量，截断也不会破坏这一性质。随后算法从每条弧的 `c_res` 中扣除 `max(0,pi_i(u)-pi_i(v))`，再处理下一个组。因为每次都只从剩余容量中扣款，全部组完成后自然满足总容量约束。**势函数 `pi_i` 会保留到整个 D/A 状态阶段结束；剩余容量 `c_res` 则只暂时保留，供第 6.2 节决定是否进行一次额外打包。**

这一初始构造还会尝试从零剩余容量弧中恢复一棵真实可行树。若恢复成功且成本更小，它只更新上界 `B`；这与势函数产生的下界是两个不同方向的结果：前者证明“已经找到这么好的解”，后者证明“任何完成方式至少还要这么多成本”。

### 3.4 统一剪枝函数

对根 `v` 和尚未覆盖的组集合 `R`，最终使用的剩余成本估计为

```text
H(v,R) = max(
    max(i in R) d_i(v),
    H_tour(v,R),
    H_cut(v,R)
).
```

三项都是合法下界，其最大值仍是合法下界。后续所有普通状态和锚定状态都只使用同一个剪枝条件：若当前部分树成本为 `c`，且

```text
c + H(v,R) > B,
```

则该状态不可能扩展成优于当前可行解的完整树，可以安全删除。

该下界不只用于状态行结束时的最后判断。每张 D/A 行开始时，算法先确定该行尚未覆盖的原始组集合 `R`；随后在两个位置调用同一个 `H(v,R)`：一是同根合并值作为种子进入队列之前，二是沿图边松弛到新根之前。队列键为 `c+H(v,R)`，因此最有希望完成的根优先弹出；当队首键已经大于 `B` 时，余下状态可以一起停止。

边容量条件还给出一致性。对任意弧 `(u,v)` 和任意剩余组子集 `R`，有

```text
H_cut(u,R) - H_cut(v,R)
<= sum(i in R) max(0,pi_i(u)-pi_i(v))
<= w(u,v).
```

所以沿一条边传播时，下界下降不会快于已经支付的边权。**第 6.2 节若加强势函数，只会发生在两张 D2 状态行之间；当前正在执行的图闭包中，下界保持不变。**加强后，新开始的状态行会读取新的 `pi_i`，已经完成的状态行不会重算。

## 4. 基于锚主干的共享汇合上界

共同根上界把每个组独立接到 `r`，没有显式利用不同组共享路径的可能性。为了在生成大规模状态前得到更紧的 `B`，算法围绕根到锚点组的一条最短路径构造一棵小型候选树。

### 4.1 锚主干与候选汇合点

从 `r` 恢复到锚点组 `T_a` 的一条最短路径，记为 `P`。该路径连接根和锚点组，因此在后续可行解中只需支付一次。以 `P` 上所有顶点为源执行多源 Dijkstra，得到每个顶点到 `P` 的距离 `d_P(x)`，并得到一棵指向 `P` 的最短路父树。

对每个由三个非锚点组构成的集合 `Q={i,j,l}`，选择一个候选汇合点

```text
x_Q = argmin_x [d_P(x) + d_i(x) + d_j(x) + d_l(x)].
```

这一点表示三个组先在 `x_Q` 汇合，再共享一条路径接入锚主干的最便宜方案。算法将所有候选汇合点到 `P` 的父路径取并集，并保留候选点、主干点和分叉点；连续的二度路径被压缩成一条等长树边。由此得到一棵规模通常远小于原图的候选树 `C`。

### 4.2 候选树上的子集动态规划

将 `C` 以锚主干为上方边界定向。对候选树结点 `x` 和非锚点组集合 `M`，定义

```text
F_x(M) = 在 x 的候选子树中服务 M，并把所用部分连接到 x 的最小成本。
```

若直接在 `x` 服务集合 `M`，可以分别沿最短路连接这些组，成本为 `sum(i in M)d_i(x)`。合并子结点 `y` 时，将 `M` 分成留在 `x` 一侧的组和交给 `y` 子树的组：

```text
F'_x(M) = min(R subset M) {
    F_x(M-R) + F_y(R) + I[R is not empty] * length(x,y)
}.
```

在全部子树合并后，根到锚点组的路径成本 `d_a(r)` 加上全部非锚点组集合 `K` 的动态规划值，构成一个合法完整解并更新 `B`。候选树限制只影响这个上界的质量，不影响主动态规划的状态空间；即使候选树没有包含最优结构，得到的仍然是一棵真实可行树，因此不会破坏精确性。

## 5. 普通状态 D：离线生成可复用分支

### 5.1 状态行与图闭包

对固定组集合 `S`，所有根顶点上的 `D(S,v)` 构成一张状态行。算法先在若干根顶点上构造同根合并候选，称为该行的种子；随后允许根沿图边移动。若种子代价函数为 `M_S(u)`，则完整状态行为

```text
D(S,v) = min(u in V) [M_S(u) + dist_G(u,v)].
```

这一从种子函数到所有根最优值的最短路变换称为图闭包。实现使用以 `H(v,R)` 为启发函数的多源 A*；队列为空，或队首状态已不可能满足 `c+H<=B` 时，该行闭包结束。

### 5.2 完整同根分解与重复消费问题

标准的同根分解会枚举 `S` 的所有非空真子集：

```text
M_S(v) = min(empty != Q proper subset S)
         [D(S-Q,v) + D(Q,v)].
```

这一递推是精确的，但同一个 `D(Q,v)` 可能本身已经能在根 `v` 继续拆分。若仍将它作为一个整体交给更高层，后续多个分割会重复读取同一组更小分支的组合结果。

### 5.3 不可拆分分支

为减少重复消费，算法固定 `S` 中编号最小的组作为枢轴 `p(S)`，并要求累计侧始终包含该枢轴。对任意非空 `Q subset S`，若 `Q` 不含枢轴，则它作为待接入分支。定义 `Br(Q,v)` 为可作为一个整体接入的普通分支值：单组集合总是分支；对多组集合，只有当图闭包后的 `D(Q,v)` 严格优于在同一根直接拆分 `Q` 的最佳种子时，才发布 `Br(Q,v)=D(Q,v)`。

普通状态的种子递推因此写为

```text
M_S(v) = min(empty != Q subset S\{p(S)})
         [D(S-Q,v) + Br(Q,v)].
```

若某个 `D(Q,v)` 等于它在根 `v` 的直接分解值，那么将 `Q` 作为整体接入与逐个接入其更小分支等价，无需再次发布。反复展开这一分解，任意标准同根递推都能表示为一个含枢轴的累计侧依次吸收不可拆分分支，因此上述递推保持完备。

### 5.4 有序状态行

状态行按 `|S|` 递增生成，因此递推所依赖的较小行总已完成。单组状态行直接引用组距离表。多组状态行根据实际存储字节数选择两种表示之一：稀疏行保存递增顶点编号及对应距离，稠密行保存按顶点编号索引的距离数组。分支资格以与行索引对齐的位图保存。

两张稀疏行通过递增列表归并求共同根；当分支数很少时，可从较短一侧做二分查找；稠密行则直接按顶点编号访问。所有选择都由当前数组长度和显式比较次数决定，不使用密度阈值，也不使用哈希表。

## 6. 普通状态阶段中的界增强

普通状态按 `|S|=1,2,...,h` 生成。随着较小状态行完成，算法逐渐获得两类此前不可用的信息：一类是能够拼成完整 GST 的真实小块树，另一类是 D2 阶段实际付出的图搜索工作。第 6 节利用这两类信息增强剪枝，但必须先区分两个完全不同的作用方向：

- **上界增强降低 `B`。** 三块与四块方法拼出一棵真实完整树；若它更好，就把 `B` 降低。之后更多状态会因为 `c+H>B` 被删除。
- **下界增强提高 `H`。** 剩余容量打包不构造完整解，也不改变 `B`；它把尚未使用的边容量继续分配给势函数，使之后的 `H_cut` 更大。

两者都不改变 D/A 状态定义和递推。它们只改变统一剪枝式右侧使用的当前 `B` 或左侧使用的当前 `H`。更重要的是，增强结果**从发生之后新生成的候选和新开始的图闭包起立即生效，但不会追溯重建已经完成的状态行**。已经保存的旧行仍然是精确值；以后读取旧行产生新候选时，新候选仍会接受当前上下界检查。

完整时序如下。令 `q_4=ceil((g-1)/4)`、`q_3=ceil((g-1)/3)`。

| 时刻 | 新获得的信息 | 执行的增强 | 改变什么 | 最早影响的后续工作 |
| --- | --- | --- | --- | --- |
| 进入 D 阶段前 | 组距离、初始 dual、锚主干 | root-star、dual primal、branch-junction | 降低 `B`，建立初始 `H` | 全部 D/A 行 |
| D2 行逐张完成时 | 已发生的 pair 图搜索工作 | 条件满足时执行一次剩余容量打包 | 提高 `H_cut` | 下一张尚未开始的 D2 行，以及全部更高 D/A 行 |
| `q_4` 层全部完成后 | 所有大小至多 `q_4` 的普通树 | 若 `q_4<q_3`，执行四块上界与有限 lifting | 降低 `B` | `q_4` 之后的 D 行和全部 A 行 |
| `q_3` 层生成过程中 | 足以覆盖全部非锚点组的三个块 | 在线检查三块完整解 | 降低 `B` | 同层尚未开始的 D 行及以后各行 |
| `q_3` 层全部完成后 | 最佳三块 witness | 对三种锚定侧做临时 lifting | 进一步降低 `B` | 更高 D 行和全部 A 行 |
| A 阶段 | 正式锚定状态 | 逐根 star upper 与逐行 `A+D+D` completion | 持续降低 `B` | 当前 A 闭包的后续传播及后续 A 行 |

例如 `g=13` 时，`g-1=12`、`h=6`、`q_4=3`、`q_3=4`，一般时间线是

```text
D1
-> D2（可能在两张 pair row 之间执行一次 packing）
-> D3 完成后执行 quarter upper
-> D4 生成时在线检查 three-block，层末执行 three-block lifting
-> D5、D6
-> 正式 A rows 与 completion。
```

这只是把通用公式代入 `g=13` 的说明例子，**算法中不存在 `g==13` 的分支或固定层特判**。

### 6.1 三块与四块可行解

令 `k=g-1`。当普通状态生成到 `q_3=ceil(k/3)` 时，任意非锚点全集都可以写成三个大小不超过 `q_3` 的不交块 `B_1,B_2,B_3`。因此对应 D 行一旦完成，就能在共同根 `v` 上计算

```text
d_a(v) + D(B_1,v) + D(B_2,v) + D(B_3,v).
```

式中的 `d_a(v)` 是从共同根连接锚点组的真实最短路，每个 `D(B_j,v)` 也是已经完成的精确普通树。四部分在同一个根相交，所以它们的并是一棵合法完整解；路径重叠只会让真实并集更便宜，因此直接相加仍是安全上界。

三块候选并不是等到整个 `q_3` 层结束才统一检查。每完成一张大小为 `q_3` 的 D 行，算法就把它与当前已经可用的另外两块组成无序分割，并扫描共同根。一个分割只有在所需三张行都已经完成时才会被检查，所以每个候选都只依赖现成精确状态。候选一旦改进 `B`，**同一层中尚未开始的 D 行就能立即使用更小的上界**。当整个 `q_3` 层结束时，所有合法三块分割都已覆盖。

当 `q_3=1` 时，所需 D 行都是直接引用组距离的隐式 singleton 行，不存在逐张构建过程；算法改在该层结束点一次性枚举全部三块候选。两种执行方式覆盖的是同一组分割。

仅在同一个根把四部分相加，仍要求锚点组和某一普通块分别接到 `v`。为了允许二者先共享一段路径再与其余两块汇合，算法保存扫描中最好的三块分割作为 witness，并依次选择三个块中的每一个作为临时锚定侧。对选择 `B_j`，先用种子

```text
d_a(u) + D(B_j,u)
```

执行一次精确图闭包，得到“锚点组加 `B_j`”在所有新根上的真实连接成本，再与另外两个 D 块在共同根合并。**三种选择是该 witness 中所有可能锚定侧的完整枚举，不是重复三次的经验参数。**三次临时闭包全部结束后，three-block 阶段结束；这些临时值只用于更新 `B`，不会写入正式 A 行，也不会被后续递推当作状态消费。

四块阶段更早发生。令 `q_4=ceil(k/4)`。当 `q_4<q_3` 且整个 `q_4` 层完成后，所有非锚点组可分为四个大小至多 `q_4` 的块。算法先只在共同根上界的固定根 `r` 处枚举四块分割：

```text
d_a(r) + D(B_1,r) + D(B_2,r) + D(B_3,r) + D(B_4,r).
```

固定 `r` 使这一步只读取每张已完成行的一个根值，因而能在正式三块扫描以前低成本尝试一次完整解。若这一基础四块解确实改进了 `B`，算法再保存最佳分割，并对四种可能的临时锚定侧分别执行与上面相同的精确 lifting closure；四种选择全部结束后停止。若基础解没有改善 `B`，则不购买四次 lifting。

当 `q_4=q_3` 时，四块信息不会比三块信息更早可用，算法跳过 quarter 阶段。无论三块或四块是否改善 `B`，都不会删除、增加或改写任何正式 D/A 状态，因此它们只影响效率，不影响完备性。

### 6.2 剩余容量打包

第 3.3 节按组依次分配势函数后，很多有向弧仍可能留有 `c_res(u,v)>0`。这些剩余容量代表原边费用中**尚未被任何组势函数用于证明下界的部分**。直接丢弃它们不影响正确性，但也失去了一次加强 `H_cut` 的机会。剩余容量打包的目标是：在不超过任何弧剩余预算的前提下，把这些零散容量同时分给多个组。

#### 6.2.1 为每个组构造候选势方向

设第 4 节得到的锚主干为 `P`。对每个组 `i`，算法在当前剩余容量图上计算顶点到 `T_i` 的有向最短距离 `d_i^res(v)`，并定义

```text
C_i = max(p in P) d_i^res(p),
q_i(v) = min(d_i^res(v), C_i).
```

`q_i` 在组内终端上为零；最短距离性质保证它在任意弧上的正下降不超过该弧剩余容量，取最小值截断后仍保持这一性质。主干 `P` 的作用是给每个方向提供一个与当前锚结构相关的有限截断尺度：主干上最难连接组 `i` 的位置决定 `C_i`，主干以外更大的距离不再继续抬高该方向。**这里没有把主干边权再次计入下界；`P` 只决定候选势函数的形状。**

单独看每个 `q_i` 都可装入剩余容量，但不能简单令所有组都取完整尺度，因为多个 `q_i` 可能在同一弧上同时产生正势差，总和会超过 `c_res`。因此还需要联合选择缩放系数。

#### 6.2.2 同步缩放而不透支任何弧

算法为每个组维护 `0<=lambda_i<=1`，初始均为零。对尚未固定的 active groups，计算每条弧在单位同步增长下承受的总负载

```text
load(u,v)
= sum(i active) max(0, q_i(u)-q_i(v)).
```

本轮所有 active groups 共同增加同一个步长

```text
Delta = min(
    min(i active) [1-lambda_i],
    min((u,v): load(u,v)>0) c_res(u,v)/load(u,v)
).
```

第一项保证没有 `lambda_i` 超过 1，第二项保证没有弧被透支。更新 `lambda_i += Delta` 后，再从每条弧的剩余容量中扣除 `Delta*load(u,v)`。达到完整尺度 1 的组被固定；若某条弧恰好饱和，所有在该弧上具有正梯度的 active groups 也被固定，因为它们已经不能继续共同增长。其余组进入下一轮。

每轮至少有一个组达到尺度 1，或至少有一条弧饱和并固定其使用者；实现若没有任何组被固定会直接判定为不变量错误。因此最多经过 `g` 轮，所有组都停止。最终势函数更新为

```text
pi'_i(v) = pi_i(v) + lambda_i q_i(v).
```

旧势函数使用的容量加上所有新增势差仍不超过原始边权，所以 `pi'_i` 继续满足第 3.3 节的逐弧容量约束。**打包只提高后续调用看到的 `H_cut`，不会更新 `B`，也不会产生任何 D/A 状态。**完成后剩余容量数组立即释放；整个 query 最多执行一次 packing。

#### 6.2.3 为什么在 D2 中决定是否购买

构造全部 `q_i` 需要每组一次全图有向最短路，同步缩放还需要扫描组与弧。对容易询问无条件执行这项预处理，可能比它节省的状态搜索更贵。ReleaseV4 因而不使用 wall time、数据集名或经验密度，而是在 D2 生成过程中累计已经真实发生的结构工作 `pair_work`：

- 每张二元行对全部顶点进行种子检查时计入 `n`；
- 初始队列 push、每次队列 pop 和成功松弛产生的 push 各计一次；
- 一个根状态被确定后，计入其实际扫描的邻接边数。

令二元普通行总数为 `C(g-1,2)`。每完成一张 D2 行，且后面仍至少有一张 D2 行尚未开始时，算法检查

```text
pair_work >= g(2m+n)
```

是否成立。右侧表示按每个组一次顶点域和两个有向弧域扫描得到的**无经验参数结构预算**。它不是用秒数预测 packing 的精确耗时，而是在已经观察到 pair search 足够重时，才允许购买一次额外的图级下界构造。

若条件成立，packing 在刚完成的 D2 行之后执行。这里 D2 指 `|S|=2` 的二元普通状态层。当前行已经使用旧 `H_cut` 完成，不会重算；**下一张 D2 行是第一张使用加强下界的行**，随后 D3--D_h 和全部 A 行也都使用新势函数。若直到只剩最后一张 D2 行时仍未购买，算法不再启动 packing；D2 层结束后直接释放剩余容量，后续阶段继续使用初始 `pi_i`。若 `h<2` 或根本没有二元行，也会立即释放剩余容量。

这一触发时机同时回答了“为何放在普通状态阶段”：D1 是直接引用的组距离，没有足够的真实搜索工作可观察；D2 是第一层执行大规模全图闭包的普通状态，也是在仍有大量 D/A 行尚未开始时能够评估投资是否值得的最早位置。购买条件只决定是否加强下界，**不决定走哪套求解框架，也不改变最终答案**。

## 7. 锚定状态 A 与精确完成

### 7.1 锚定状态递推

锚定状态的基本行为

```text
A(empty,v) = d_a(v)
```

表示从根 `v` 连接锚点组。对非空 `S`，算法选择一个非空普通分支集合 `Q subset S`，其余组继续留在已有锚定侧：

```text
N_S(v) = min(empty != Q subset S)
         [A(S-Q,v) + Br(Q,v)].
```

随后执行图闭包：

```text
A(S,v) = min(u in V) [N_S(u) + dist_G(u,v)].
```

由于每次转移只有左侧包含锚点，所有锚定状态天然共享同一个逻辑主干，不会产生两个彼此竞争的锚定侧。普通分支仍使用第 5.3 节的不可拆分表示，因此 A 递推不会重新引入完整 D 子集分割的重复消费。

### 7.2 逐行可行解更新

在 `A(S,v)` 的图闭包过程中，任一已确定根状态都可以把尚未覆盖的组分别接到同一根，形成可行解

```text
A(S,v) + sum(i in K\S) d_i(v).
```

算法用它即时更新 `B`。这使锚定状态不仅消费前面建立的上界，也在自身传播过程中持续产生新的上界。

### 7.3 A+D+D 完成式

一张 A 状态行完成后，令剩余组为 `K\S`。算法枚举其无序二分 `L union R=K\S`，并在共同根上计算

```text
A(S,v) + D(L,v) + D(R,v),
```

其中空集合的 D 值定义为零，且 `|L|,|R|<=h`。A 行与两张 D 行都按根顶点排序，因此可以选择最短列表作为驱动，另外两张列表只做单调扫描。

算法只生成 `|S|<=h-1` 的 A 状态行。最高层 A 状态行完成上述扫描后不再保存，因为不存在更高层消费者。当所有规定大小的 A 状态行都完成时，算法终止并返回当前 `B`。

## 8. 正确性分析

### 8.1 上下界安全性

共同根上界、候选树上界、三块与四块上界都由真实图路径和已经完成的精确状态组成，因此每次对 `B` 的更新都对应某个合法完整解。组间路径下界和边容量势下界都不超过任意真实剩余连接成本；剩余容量打包只使用尚未分配的容量，因此加强后的下界仍然合法。由此，剪枝条件 `c+H>B` 不会删除可能达到最优值的状态。

### 8.2 普通分支递推的完备性

考虑标准同根递推产生的任意最优 `D(S,v)`。若其右侧子树在根 `v` 仍可拆分，则将其继续展开；每次展开都严格减小子集大小，因此最终得到若干单组分支或不可继续在 `v` 拆分的普通分支。固定枢轴所在的部分作为累计侧，依次吸收其余分支，即可得到第 5.3 节递推中的一条等价构造序列。因此只发布不可拆分分支不会丢失任何最优普通状态。

### 8.3 锚定递推与完成式的完备性

在任意最优 GST 中，把锚点组命中的顶点视为属于唯一锚定部分。沿树逐步移除不含锚点的根分支，可以把锚定部分表示为 A 递推依次吸收普通分支的过程，因此 A 状态覆盖最优树中所有可能的锚定侧。

进一步地，把每个终端组视为一个计数单位。树上存在一个平衡结点，使删除该结点后每个连通分量包含的终端组数不超过 `h`。把含锚点的若干分量与平衡结点合并为 A 侧，其余分量合并为至多两个 D 侧，可以保证三侧大小分别不超过 `h-1`、`h`、`h`。因此某个 `A(S,v)+D(L,v)+D(R,v)` 必然表示一棵最优树。

综合上述结论，算法维护的 `B` 始终是可行解上界，而状态空间必然包含一个成本等于全局最优值的完成式。算法结束时返回的 `B` 因而等于精确最优值。

## 9. 复杂度分析

令 `P` 为实际生成的多组 D/A 状态行数量，最坏为 `O(2^(g-1))`；令 `L` 为所有已保存状态行中的根值总数；令 `|C|` 为共享汇合候选树压缩后的结点数。优先队列按二叉堆实现计入对数因子。

组距离需要 `O(g(m+n)log n)` 时间和 `O(gn)` 空间。组间 Hamiltonian-path 下界需要 `O(2^g g^3)` 时间和 `O(2^g g^2)` 空间。边容量势构造需要 `O(g(m+n)log n)` 时间和 `O(gn+m)` 空间。

共享汇合上界需要

```text
O(m log n + C(g-1,3)n + |C|3^(g-1)) time,
O(n + |C|2^(g-1)) space.
```

D/A 子集转移、阶段性完成和最终完成的保守总枚举量为 `O(3^(g-1)n)`。每张实际状态行至多执行一次图闭包，因此全部正式状态行闭包为 `O(P(m+n)log n)`。若执行剩余容量打包，额外时间为 `O(g(m+n)log n+g^2m)`，额外空间为 `O(gn+m)`。

由此得到保守总时间

```text
O(2^g g^3
  + (g+P)(m+n)log n
  + g^2m
  + (C(g-1,3)+3^(g-1))n
  + |C|3^(g-1)),
```

其中 `g^2m` 项只在执行剩余容量打包时出现。保守总空间为

```text
O(Pn + 2^g g^2 + gn + m + |C|2^(g-1)).
```

最坏情况下每张状态行可以包含全部顶点，因此出现 `O(Pn)`；实际实现以稀疏或稠密有序行保存状态，状态行实际空间为 `O(L)`。方法通过更紧的上下界和不可拆分分支接口减少 `L` 与实际闭包工作，但不把这种实例相关削减写成更低的最坏情况复杂度。
