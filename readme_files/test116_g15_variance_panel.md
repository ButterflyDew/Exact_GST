# Test116：DBLP g15 跨询问压力筛查与 q33 完整结果

更新时间：2026-07-15。本文补充 Test115 只运行 query 1 的证据缺口。目标不是用少量样本估计 40 条询问的平均时间，而是优先寻找会推翻“DBLP g15 每条询问都能在 10,000 秒内完成”这一命题的困难询问。Test116 不改变 Test107 算法，只增加一个在普通状态 D3 自然完成后退出的诊断二进制。

## 1. 为什么不能只看 q1

DBLP 的 40 条 `g=15` 询问分成四档，每档 10 条，组顶点总数依次增大：

| 查询档 | 组顶点总数范围 | 中位数 |
| --- | ---: | ---: |
| q1--q10 | `2,838--3,207` | `3,022.5` |
| q11--q20 | `5,613--6,261` | `5,826` |
| q21--q30 | `11,068--12,078` | `11,712.5` |
| q31--q40 | `22,043--25,527` | `24,403` |

q1 只有 `3,124` 个组顶点，属于第一档。更重要的是，运行时间不仅由组顶点数决定，还取决于组在图上的位置、上界质量以及各层保留下来的根状态。因此，q1 的完整结果只能证明 q1，不能代表四档询问的方差或最坏情况。

已有 DBLP `g=13` Test80 记录也直接显示了这种波动：19 条新增跨询问记录加上历史 q1，共有 20 条已完成询问。其 wall 最小值为 `276.117s`，中位数为 `1939.544s`，均值为 `2133.293s`，最大值为 `7619.938s`；样本标准差为 `1635.347s`，变异系数约 `0.77`，最大值是最小值的约 `27.6x`。其中 q1 为 `666.509s`，只有该批中位数的约 `34.4%`。这组记录来自较早的 Test80 组合版，不能替代当前 Test107 的 g15 实测，但足以说明**把 q1 当作典型询问在实验设计上不严谨**。

## 2. 样本选择与诊断边界

每档先选择一条压力样本：`q2、q14、q25、q33`。选择依据是同一编号在已有 DBLP `g=13` 跨询问记录中属于该档已完成样本里较慢的询问，其历史 wall 分别为 `1762.928s、2448.019s、7619.938s、2917.923s`。这是一组**有意偏向困难询问的反例筛查样本**，不是随机样本，也不能用于估计总体均值或方差。

筛查使用 `gst_test80_d3_probe_main`。它与正式 Test107 编译同一份求解源码，完整执行公共预处理、D1、D2 和 D3，然后退出。选择 D3 是因为早期 Test18 的首次状态爆炸就在 D2/D3 边界；该边界可在进入更昂贵的高层前暴露 pair/triple 行是否接近全图稠密。探针不执行 D4--D7、A 阶段和最终完整化，`weights.txt` 中的 `best=-1` **不是 GST 答案，probe wall 也不是完整求解时间**。

## 3. D3 压力筛查结果

全部运行使用 Release/O2，结果保存在 `result_snapshot/gates/20260715_test116_g15_d3_panel`。表中 peak 是该条探针询问的采样 peak RSS。

| query | 组顶点 | D2 values | D2 time | D3 values | D3 time | probe wall | peak RSS |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| q2 | `2,838` | `9,787,431` | `65.699s` | `10,040,910` | `74.513s` | `198.435s` | `2308.4MiB` |
| q14 | `5,613` | `5,744,907` | `58.050s` | `5,275,998` | `60.472s` | `178.424s` | `2267.0MiB` |
| q25 | `11,668` | `74,060,371` | `209.354s` | `163,748,795` | `440.318s` | `710.037s` | `3678.9MiB` |
| q33 | `22,927` | `153,152,104` | `397.720s` | `419,590,120` | `1015.769s` | `1482.100s` | `6319.9MiB` |

作为参照，完整 q1 的 D2/D3 values 为 `19,080,397/24,951,889`，对应层时间为 `90.908s/133.889s`。q14 的组顶点更多但前三层反而比 q2 更轻，说明不能用查询规模单调预测耗时；q33 的 D2/D3 values 则分别是 q1 的约 `8.0x/16.8x`，D3 单层已经超过 q1 全部 D3 时间的 `7.5x`。因此，跨询问方差确实很大，Test115 的 q1 结果不能支撑整个 DBLP g15 的统一时间结论。

q33 在四条压力样本中同时具有最高 D3 状态量、D3 时间和 peak RSS，故下一步只选择 q33 做完整压力门。这样做的结论边界仍然明确：q33 可以检验当前已知高风险样本是否低于 10,000 秒，但不能估计 40 条询问的均值或方差。

## 4. q33 完整压力门

完整运行使用同一 `gst_test80_progress_main`，只在每个 D/A 层自然结束后输出统计，不按数据集、固定 `g`、层号、密度或 wall time 改变求解策略。原始结果固化在 `result_snapshot/gates/20260715_test117_g15_q33_full`，其中 `weights.txt` 第三列是该条 query 的采样 peak RSS。

| 指标 | q33 完整结果 |
| --- | ---: |
| exact best | `8.3053688653` |
| query wall | `11505.101235s` |
| solver total | `11503.303820s` |
| query peak RSS | `19228.398MiB` |
| 相对 10,000 秒 | **超出 `1505.101s`，即 `15.05%`** |

普通 D 阶段为 `7018.495s`，占 solver total 的 `61.01%`；锚定 A 阶段为 `4419.560s`，占 `38.42%`。completion 包含在 A 阶段中，共 `288.872s`，只占 solver total 的 `2.51%`，不是本条询问越过阈值的主因。

### 4.1 普通状态层

| 层 | values | row bytes | closure time | 层后 best |
| --- | ---: | ---: | ---: | ---: |
| D2 | `153,152,104` | `1,296,247,792` | `410.648s` | `10.2642201136` |
| D3 | `419,590,120` | `3,640,844,800` | `1025.343s` | `10.2642201136` |
| D4 | `781,846,242` | `7,007,798,588` | `1944.255s` | `10.0181663554` |
| D5 | `205,983,275` | `2,036,446,412` | `1077.484s` | `8.6590457499` |
| D6 | `32,003,569` | `385,326,576` | `1104.796s` | `8.6590457499` |
| D7 | `16,272,337` | `197,104,696` | `1438.464s` | `8.4170052850` |

D2、D3、D4 平均每行分别保留约 `67.38%`、`46.15%`、`31.27%` 的全图顶点，随后 D5--D7 才降到 `4.12%`、`0.43%`、`0.19%`。因此 q33 最终确实收缩，但收缩发生在 D4 已产生 `781.85M` 个状态并消耗 `1944s` 之后，无法挽回前半段的主要代价。

| 层 | values | row bytes | completion | layer time | 日志 best* |
| --- | ---: | ---: | ---: | ---: | ---: |
| A1 | `14,286,605` | `120,849,544` | `25.683s` | `68.897s` | `8.4170052850` |
| A2 | `50,026,177` | `442,827,992` | `35.078s` | `192.967s` | `8.4170052850` |
| A3 | `105,899,857` | `999,684,564` | `49.459s` | `427.131s` | `8.4170052850` |
| A4 | `143,950,170` | `1,482,091,908` | `64.548s` | `764.655s` | `8.4037383270` |
| A5 | `135,438,856` | `1,504,485,200` | `66.199s` | `1234.404s` | `8.3053688653` |
| A6 | `96,564,896` | streamed | `47.904s` | `1730.497s` | `8.3053688653` |

A6 不持久保存 row，空间峰值仍主要由已保留的 D3--D5 与 A3--A5 行共同形成；但流式只消除了顶层持久存储，没有消除 A6 的连接和传播，所以 A6 仍是全程第二慢的单层。

`*` A5 producers 与 A6 consumers 是交错执行的；当前实现等整个流式联合阶段结束后，才把同一个最终 best 写入 A5/A6 两个字段。因此表中的两个 `8.3053688653` **不能判断 exact 首次来自 A5 还是 A6**。Test129 的 7/4/4 反例已证明这种共享日志会掩盖 A6 的必要更新，见 `archive/test129_penultimate_a_completion_20260716.md`。

## 5. 结论与实验边界

q33 的 wall 是 q1 的 `5.89x`，query peak RSS 是 q1 的 `5.92x`。因此当前证据应写成两个不同结论：

1. **Test107 可以在 10,000 秒内完成 DBLP g15 q1。** 这是 Test115 已证明的单例结论。
2. **“Test107 对 DBLP g15 的每条询问都低于 10,000 秒”已经被 q33 否定。** q33 实际耗时 `11505.101s`，不是由探针外推得到。

这次有意选择困难询问，因此 q33 是有效的反例与压力结果，却不是无偏样本。q2/q14/q25 只有 D3 截止数据，也不能与 q1/q33 的完整 wall 混合计算 g15 均值、标准差或分位数。若论文需要报告 DBLP g15 的总体时间分布，应完整运行 40 条询问，或预先声明一个与运行结果无关的分层抽样协议并只对该样本作统计；当前文档不作这类外推。

## 6. 复现与验证

`gst_test80_main`、`gst_test80_progress_main` 和 `gst_test80_d3_probe_main` 均重新以 Release 构建，编译命令确认启用 `/O2 /Ob2`。正式 Test80 与 DPBF 的黑盒对拍为：宽范围 `g=2--8`、seed `717151`、`50/50` 通过；固定 `g=15`、seed `717152`、`20/20` 通过。q33 临时结果与固化副本的 `test80_stats.txt`、`weights.txt` SHA-256 均逐文件一致；临时运行与随机对拍目录已经清理。
