# Test149：只从已改写弧启动 dual 残量闭包

更新时间：2026-07-17。Test149 在 Test146 上只改动 sequential dual-cut potential 的构造过程，不改变 dual 的定义、组顺序、势函数、普通 D、伴随 H、最终答案或 ReleaseV4。它解决五数据集剖析中暴露出的一个具体问题：对 MovieLens 这类“图很大、后续状态很轻”的询问，dual 本身有效，但构造时反复全图扫描的固定成本过高。

后续状态：Test149 已冻结进入 ReleaseV5；Test152 复用这里完全相同的逐组顺序与 changed-arc 闭包，但按 ordinary 工作量渐进购买各组前缀，并经 Test157 审计后冻结进入 ReleaseV6，见 `test152_progressive_dual.md`。ReleaseV5 仍保留 Test149 的 eager 完整构造。

## 1. 原实现为什么重复扫描全图

设无向边的两个方向分别视为弧，原始边权为 `w(u,v)`。处理第 `i` 个组之前，dual 已经用前面各组的势更新出非负残量 `r_i(u,v)`。当前组先读取它在原始边权上的组距离 `d_i(v)`，再求 `r_i` 下的精确最短路闭包。

旧实现对每个后继组都枚举全部 `2m` 条有向弧，检查

```text
r_i(u,v) + d_i(v) < d_i(u)
```

若成立，就把 `u` 放入 Dijkstra 队列；随后再从这些违反三角不等式的位置传播。该过程正确，但一条弧即使从未被前面势函数改变，也会被每个后继组重复检查。`g=15` 时，初始化阶段最多执行 `14 * 2m` 次弧检查。

## 2. 核心观察

`d_i` 是原始边权 `w` 下的最短距离，因此对每条有向弧都满足

```text
d_i(u) <= w(u,v) + d_i(v).
```

如果一条弧在此前从未被 dual 势降低，那么 `r_i(u,v)=w(u,v)`，上式已经证明它不可能成为残量闭包的初始违反点。**所以，初始化 Dijkstra 时只需检查残量曾被前面某个组降低过的弧。**

这不是近似筛选。未改写弧由原始最短路三角不等式直接排除；已改写弧仍逐条做原来的精确比较。队列启动后，Dijkstra 仍扫描完整邻接表，因此由违反点继续传播到未改写弧的路径不会丢失。

## 3. 算法流程

Test149 为 `2m` 条有向弧维护一个累计 bitset `changed`，初始为空。第一个组无需残量修复，直接使用原始组距离。以后每个组按以下步骤处理：

1. 从当前组的原始组距离复制 `distance`。
2. 按机器字枚举 `changed` 中的置位弧，并执行旧实现相同的残量违反检查。
3. 把所有严格改善的端点放入 `std::priority_queue`，在完整残量图上执行 Dijkstra 闭包。
4. 按原规则在根集合处截断势函数，并扫描全部边更新两个方向的残量。
5. 若当前势在某个方向具有正梯度，就把对应有向弧永久加入 `changed`。

`changed` 是累计集合：弧一旦被改写，后续组都会重新检查它。实现没有 Hash，也没有按数据集、`g`、层号、密度或时间切换路径。

## 4. 正确性

**引理 1：未改写弧不会是初始违反点。** 若弧 `(u,v)` 不在 `changed` 中，则此前没有势降低该方向的残量，因此 `r_i(u,v)=w(u,v)`。由原始组距离的三角不等式，`r_i(u,v)+d_i(v)>=d_i(u)`。

**引理 2：检查改写弧足以启动全部必要传播。** 从原始 `d_i` 出发，任何第一次严格降低某个顶点的弧必在 `changed` 中。Test149 检查其中每一条；若端点已经被更强路径降低，则无需重复入队，否则就用与旧实现相同的残量和比较式将其入队。

**引理 3：两种实现得到相同的残量最短路闭包。** 旧实现的全弧预扫描可能顺便沿未改写弧提前传播，但这些只是随后 Dijkstra 会执行的松弛。Test149 已由引理 2 放入所有必要的首次降低点，之后在同一非负残量图上扫描完整邻接表，因而也会完成这些传播，最终距离逐点相同。

由引理 3，每组的截断势、dual objective 和残量更新均与旧实现相同。对组序归纳可知全部组的势逐点相同，因此 Test149 的所有下界、剪枝、状态和最终答案均保持不变。

## 5. 复杂度与空间

设处理第 `i` 个后继组时累计改写弧数为 `c_i`。旧初始化扫描量为 `(g-1)2m`；Test149 的置位弧检查量为 `sum_i c_i`，另有 `O(gm/64)` 的 bitset 机器字遍历。最坏情况下 `c_i=2m`，渐进时间仍为 `O(gm)`；当改写弧稀疏时，初始化常数显著下降。残量更新和 Dijkstra 的最坏复杂度不变。

额外空间为 `2m` bits，即约 `m/4` bytes。MovieLens 的 `m=35,323,774`，对应约 `8.42MiB`；其余四图更小。该 bitset 只记录 dual 自己已经修改的方向，不压缩输入图，也不是 baseline 可直接共享的通用查询预处理。
