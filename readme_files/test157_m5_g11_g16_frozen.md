# Test157 M5 三图 `g=11..16` 冻结面板

更新时间：2026-07-18。本文只记录冻结后的 M5 在 GPU4GST Musae、Twitch 和 Github 三张图上的高档 CPU 可运行性。它回答的是“固定查询在统一协议下能完成到什么程度”，不是正确性证明，也不是与 GPU4GST 作者实现的同机性能比较。

## 1. 运行协议

- 方法固定为 `gst_test157_m5_progressive_dual_main`，使用当前 Test80 源码和 MSVC Release `/O2 /Ob2`；运行期间没有数据集、`g`、查询编号、密度或 wall-time 算法分支。
- 每张图的 `g=11,12` 固定运行查询文件前 20 条，`g=13..16` 固定运行前 5 条。一个 `<dataset,g>` 在同一进程内连续执行，图只加载一次。
- 单询问上限为 1000 秒。已完成查询的时间取 `weights.txt` 第一列 solver wall，空间取第三列 query peak RSS；超时不伪造时间或 RSS，也不进入已完成查询的均值。
- Github `g=16` 的 q2 在 q1 写回后约 1018 秒仍未产生结果，外部终止该批处理进程。故该档记为 q1 完成、q2 超时、q3--q5 未启动，而不是把后三条也记为超时。
- 不同 `g` 使用不同查询，表中相邻行不能直接解释为严格的指数增长倍率。

本轮结果位于 `result_snapshot/v6_review/20260718_test157_m5_g11_g16_frozen`。所有结果文件只有一个 run header，没有混入历史追加记录。

## 4. M4/M5 高档同源核对

Musae 的相同 q1--q5 同时存在 M4 结果，可用于检查“progressive dual 在高档一定回退”的早期判断。结果并非单一方向：

| `g` | M4 q1--q5 | M5 q1--q5 | `M4/M5` | 结论 |
| ---: | ---: | ---: | ---: | --- |
| 13 | 12.056s | 12.315s | 0.979x | M5 慢 2.15% |
| 14 | 55.828s | 52.513s | 1.063x | M5 快 5.94% |
| 15 | 110.862s | 97.973s | 1.132x | M5 快 11.63% |
| 16 | 609.384s | 563.019s | 1.082x | M5 快 7.61% |

另外，Musae g13 的完整 q1--q20 仍为 M4/M5 `109.533/111.782s`，保留 M4 快约 2.05% 的负面结果。高档核对因此支持“冻结一个统一的 M5 路线”，但不支持“M5 对每个档都更快”的表述，也不允许据此增加按 `g` 切换 M4/M5 的特判。

## 5. 评审结论与边界

**GPU4GST 三图 `g=11..16` 冻结面板的数据收集已完成。** 它证明当前 M5 在 Musae/Twitch 的选定最大档可完成，也暴露了 Github g16 的真实长尾与内存增长；论文实验必须同时报告二者，不能只报成功档均值。

该子门通过不代表 ReleaseV6 效果门通过：传统 Toronto、DBLP、DBpedia、LinkedMDB、MovieLens 的冻结多询问面板仍未完成。当前机器只有 2 GiB GeForce GT 730，不能运行面向 A6000 级硬件的 GPU4GST 作者实现，因此同机 GPU 对照也仍未通过。高档查询缺少可在合理时间内完成的 DPBF/Strict PrunedDP++ 参考，本轮只能作为生产可运行性证据，不能替代随机小图和低档逐条正确性对拍。
