# Test157 生产实现审计与 M5 路线冻结

更新时间：2026-07-18。本文审计 Test157 进入 ReleaseV6 前最容易被证明稿遗漏的三类问题：**稀疏行表示是否保持语义、residual packing 是否在浮点运算后仍满足 dual 容量、progressive dual 的每个部分前缀是否都合法。** 最后一节给出 M4/M5 的单一路线取舍。该审计现已通过并用于冻结 ReleaseV6；本文仍是研究证据，不替代正式方法文档。

## 1. 稀疏行不变量

新增 Release/O2 审计目标 `gst_test157_production_audit_main`。它与已冻结的 M5 使用相同算法配置，只通过编译期 `GST_TEST157_VALIDATE_ROWS` 在 ordinary、anchored 和 backward 行完成存储后检查表示，不改变候选、剪枝或答案。检查内容包括：

- dense、ranked-bitmap、sparse 三种模式互斥；位向量长度和尾位正确；
- sparse 顶点严格递增且无重复；rank 前缀等于此前位数；值数等于 popcount；
- 所有已表示代价有限、非负且小于 `kInf`；顶点 0 不进入状态行；
- branch 位只指向本行已有值，`branch_count` 等于实际位数；anchored/backward 行不携带 branch 负载。

黑盒随机对拍使用 seed `157158`，在 `n=4..11、g=2..7` 的 1000 个实例上逐条与 DPBF 一致。真实图又运行 GPU4GST Musae/Github `g=12` 前 5 条，共 10 条查询；审计器实际检查 ordinary dense/bitmap/sparse 行 `17/2950/11773` 张、anchored bitmap/sparse 行 `263/355` 张，以及 backward 行 `9570` 张，未触发异常。dense 分支由 Github 的真实查询实际覆盖，不是只靠静态代码检查。

结果位置：`result_snapshot/v6_review/20260718_test157_production_audit_m5_real`。随机逐例临时目录和被 M5 替代的 M4 审计快照均已清理。

## 2. Packing 的直接 dual 证书

`tools/dual_cut_probe` 新增 `--packing-self-check`。每个随机实例先构造完整 changed-arc sequential dual，再从 permanent root 到随机顶点取一条真实图路径并执行 `StrengthenAlongPath`。packing 完成后不只比较最终 GST 答案，而是直接检查：

1. 每组势在该组全部终端上为 0，其他顶点势有限且非负；
2. 对每条无向边的两个方向，所有组的正势降之和都不超过边容量；
3. 每个非空 mask、每个根上的势和不超过 exact rooted DP；
4. 每条边上的一致性和所有 `mask/submask/from/to` splice 不等式成立；
5. packing 轮数属于 `[1,g]`，各组 scale 有限且属于 `[0,1]`。

随机生成器显式包含零权边、重叠组、每组多个候选，并按实例使用 `1e-6/1/1e6` 三档全图权重尺度。最初的固定 `1e-8` 审计容差在一条权重 `1.2e7` 的边上报告了约 `1.1e-8` 的舍入差；逐项诊断确认势差正好等于边权，仅绝对容差不随尺度增长。审计器因此统一使用 **`1e-10 * max(1, |参与值|)` 的尺度相关容差**，求解器和 packing 算法没有为通过测试而改变。

最终 Release/O2 运行 seed `15715703`，3000/3000 个实例通过：检查 26,695 个组终端、82,152 个有向容量、905,012 个 rooted mask 下界、1,643,624 个局部一致性约束和 98,848,900 个 splice 条件。原不含 packing 的 full-dual 模式另以 seed `15715704` 通过 1000/1000 个实例。

## 3. Progressive dual 前缀

`--progressive-self-check` 从空势开始，每次只调用一次 `AdvanceProgressiveChangedArcs`。在每个前缀结束后，独立检查终端零势、非负势、两个方向的总容量、全部 rooted mask admissibility 与边一致性；完成全部 `g` 组后，再把每个 `<mask,vertex>` 与 eager changed-arc 构造逐点比较，并比较组顺序和恢复的 primal upper。

Release/O2 seed `15715706` 的 2000/2000 个缩放随机实例通过：共检查 8977 个部分前缀、92,646 个终端、248,664 个有向容量、3,783,922 个 rooted mask 下界、6,911,572 个一致性约束，并完成 616,908 次 progressive/eager 逐点等价比较。因此 M5 在 row 边界启用任意长度前缀时只会改变下界强度，不会改变精确状态语义。

## 5. 单一路线冻结判定

**后续 Test 和潜在发行实现冻结为 M5；M4 只保留为同源消融目标。** 理由不是按 `g` 选择赢家，而是使用一个对所有查询相同的确定性规则后，420 条配对总时间降低 2.68%，逐询问赢 271/420，平均 query peak RSS 降低 5.10%，并消除了小 `g` 最重的无条件预处理；Musae g14--16 的同源结果又表明该选择没有造成系统性高档回退。最终方法不得加入 `g>=x`、数据集、查询编号、密度或 wall-time 分支来追逐单档赢家。

调度中的单位预算 `2m+n` 来自一个 dual 组涉及的 `2m` 个有向 residual 容量和 `n` 个势位置；租用工作只累计已经实际发生的 seed、queue pop 和 relax。该规则没有可拟合常数，但它**不是** dual Dijkstra 真实时间的严格上界，也没有竞争比。因此论文只能把 M5 称为数据无关的确定性渐进调度，并完整消融；不能把它称为理论最优购买策略，也不能把它并入 `D/A/F/H + transpose` 的核心新颖性。

## 6. 当前评审结论

生产稀疏行、packing 数值安全、partial dual 正确性和 M4/M5 取舍四个子门现已通过；GPU4GST 三图 `g=11..16` 的冻结数据也已收集完成，共完成 176/180 条，Github g16 q2 触发唯一 1000 秒 cutoff。按“完整方法是否形成清楚、有效、无工程特判且可复现的主线”这一评审尺度，方法冻结门已经通过，M5 已独立清理为 ReleaseV6。传统五库完整面板、可用 CUDA 硬件上的 GPU4GST 同机对照，以及扩大的引文链仍是投稿实验与相关工作缺口，不能被写成已经完成，也不再被混作阻止发行代码冻结的算法缺陷。
