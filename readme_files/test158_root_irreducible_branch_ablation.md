# Test158：root-irreducible branch 的独立消融

更新时间：2026-07-18。本文只回答一个问题：普通状态中只发布 strict root-irreducible branch，是否形成了区别于标准同根合并的强独立机制，并足以恢复 ReleaseV6 的新颖性主线？实验结论是：**它是正确且能减少确定性工作量的规范化辅助，但当前时间收益小且受运行噪声影响，没有空间收益，也没有改善最坏复杂度；不能作为论文核心。**

## 1. 被消融的唯一变量

对非空普通组集合 `S` 和根 `v`，令 `M_S(v)` 为同根二分合并得到的最小 seed，令图闭包 `C` 把 seed 沿最短路传播，则标准普通状态为

```text
D_S = C(M_S).
```

冻结 M5 不把每个 `D_S(v)` 都交给后续同根合并，而只发布

```text
Br_S(v) = D_S(v),  if |S|=1 or D_S(v)<M_S(v);
Br_S(v) = infinity, otherwise.
```

直观上，若 `D_S(v)=M_S(v)`，该值在根 `v` 处仍能拆回产生它的两个普通侧；后续合并可以把其中一侧重新结合到累计侧，因此没有必要把整个 `S` 再作为一个不可分 branch 发布。`test152_core_correctness.md` 的 branch-basis completeness 定理已经证明，以 `Br` 限制 pivot-free 一侧仍逐点产生与标准递推相同的 `M_S` 和 `D_S`。

生产代码带 admissible incumbent 剪枝，因此实现只比较本行实际通过界的值：`split_distance[v]` 记录闭包前被接受的最佳 seed，`row_distance[v]` 记录闭包后的值；冻结 M5 仅在 `row_distance[v]<split_distance[v]` 时发布该根。Test158 的 `GST_TEST158_ALL_BRANCHES` 编译期消融把这一行改为“发布所有 settled `D_S(v)`”。**两者除此之外完全相同：永久锚点、`F/H`、转置终端、上下界、渐进 dual、行表示、查询顺序与输出均未改变，也没有运行时开关或数据依赖特判。**

全分支版本仍然精确：它加入的每个值都是一个精确的可行普通状态，只会增加可重新结合的冗余候选。由于额外候选可能更早改善 incumbent，带剪枝生产运行中的后续 settled 行不要求严格形成集合包含关系；这不影响答案等价性，也解释了两个版本的 `ordinary_values` 可以有极小差异。

## 2. 正确性核验

Test158 使用三层互补证据。

1. Test157 独立 verifier 不调用生产递推，已经比较 strict restricted DP 与 standard canonical DP 的 `1,956,213` 个 `(mask,root)` 单元，全部相同。
2. `gst_test158_all_branches_main` 以种子 `158001` 对 DPBF 运行 500 个随机实例，范围为 `n=4..11`、`g=2..7`，结果 `500/500 ALL_OK`。
3. 下述真实数据两轮共 240 对逐询问结果，最优权重全部相同。

因此，本消融测量的是同一精确算法中的 branch 发布策略，而不是用答案差异换取速度。

## 3. 冻结协议

- 数据：GPU4GST Musae、Twitch、Github。
- 查询：每个数据集的 `g=9`、`g=10`，各取 `q1..q20`。
- 重复：两轮；第二轮在每个数据集／`g` 单元内交换 M5 与全分支版本的执行次序。
- 构建：CMake `Release`，MSVC `/O2 /Ob2`。
- 时间：`weights.txt` 第一列的逐询问 solver wall time；不含跨进程外部脚本等待。
- 空间：`weights.txt` 第三列的逐询问 query peak RSS。
- 配对：同一数据集、同一 `g`、同一查询编号逐条比较；`M5 wins` 表示 strict 版本墙钟更短。

## 6. 为什么不能进一步只存 `Br`

branch-basis completeness 还可以推出一个更强的表示恒等式。忽略生产剪枝、只看精确数学状态，对任意 `S,v`，

```text
D_S(v) = min over partitions P of S  sum_(B in P) Br_B(v).
```

一边很直接：每个 `Br_B(v)` 都是以 `v` 为根的真实普通树，把分区中的树在 `v` 合并仍是覆盖 `S` 的可行树，所以分区和不小于 `D_S(v)`。反方向对 `|S|` 归纳：若 `D_S(v)` 自身被发布为 `Br_S(v)`，取单块分区；否则 `D_S(v)=M_S(v)`，branch-basis 定理给出 `D_A(v)+Br_B(v)` 的等值分解，再递归展开 `D_A(v)` 即可。

这个恒等式说明 `Br` 是一组同根生成元，但**不自动产生更小的求值算法**。要从生成元恢复所有未来需要的 `D_S(v)`，仍需计算 min-plus subset-partition closure。行式实现保存累计值 `D_A(v)`；根式实现则要保存等价的分区值 `P_A(v)`，或者在每次消费时重算。前两者在最坏情况下仍有 `O(n2^k)` 累计状态和 `O(n3^k)` 不相交组合关系，后一种只会增加重复工作。Test158 的 RSS 结果也直接说明：当前 bitset 行中只减少 branch 消费次数，并不会删除累计状态值。

同一个原因阻止了另一种看似直接的简化。高层 `H_T` 的直接终端枚举补集 `U=K\T` 的 `D_L(v)+D_R(v)`；若完整 `D_U` 行已经存在，当然有 `D_U(v)<=D_L(v)+D_R(v)`，可以用单行替代。但冻结切分只计算 `|U|<=h=floor(g/2)` 的普通行，而高层终端的大多数补集都满足 `|U|>h`：奇数 `g` 时全部如此，偶数 `g` 时只有最高的 `|T|=h-1` 一层恰好有 `|U|=h`。为其余目标补算 `D_U` 会重新引入被 MITM 删除的上半层闭包；用 `Br` 分区恢复它们，则退化为当前转置终端已经执行的 min-plus packing 关系。

因此，**“只存 `Br`”目前是一个正确表示，不是新的状态／复杂度突破。** 若未来要沿此方向重开 Test，必须先给出严格小于累计 `D/P` 闭包的存储界或事件界，而不能只把行式求值改写成按根分区。

## 7. 评审结论

strict `Br` 的正确定位已经明确。

- **正确性：通过。** 它是 standard canonical DP 的完备规范化基，严格 `<` 不因等值、零权边或共享组代表而漏解。
- **工程作用：存在但较小。** 在本面板中减少 `15.69%` 的 branch 发布、`11.42%` 的普通拼接工作和 `5.59%` 的锚定拼接探测；两轮总墙钟仅为 `1.018x`，且反序轮持平。
- **空间作用：未发现。** 主状态值和 branch 位图域仍需保存，平均与最大 query peak RSS 均无改善。
- **复杂度：没有改善。** strict 与全分支版本仍有相同的最坏状态数、闭包数和 `O(3^k)` 组合事件界。
- **新颖性：不足。** canonical split 与 PrunedDP++ conditional merging 已经提供相邻先例；当前新增的是一个有完备性证明的具体规范化基，但没有新的渐近界或足够强的独立效果。

因此冻结 M5 可以继续保留 strict `Br`，因为它没有经验参数、证明清楚且净减少工作；论文中最多把它写成辅助引理和实现优化。**Test158 没有恢复 Test152 的论文级原创核心，ReleaseV6 仍不得创建。**
