# Test80：DBLP g13 跨询问剖析

更新时间：2026-07-15。本报告研究 Test80，也就是 ReleaseV4 清理前、带完整统计的纯框架 A 实现。实验只增加计数器，不改变状态、上下界、行表示、执行顺序或终止条件。这里的绝对时间包含统计开销，作用是比较不同询问及不同阶段，不替代 ReleaseV4 的发行性能。

## 1. 研究目标

此前 DBLP g13 只有 q1 的完整分阶段数据。单个询问不足以判断瓶颈是否稳定，因此本轮在其他询问上回答四个问题：主要时间究竟位于普通状态 D、锚点状态 A 还是最终完整化；峰值空间由哪一类、哪一层有序行产生；现有上下界在何时改善 incumbent，又在候选生成后的哪一步淘汰工作；离线有序列表连接主要使用哪种路径，下一步能否继续保持无 Hash 的框架。

本轮不是提出新算法，也不把普通图压缩或询问压缩计作本方法贡献。所有后续建议都必须从状态语义或可证明的工作量关系推出，不能按数据集名、询问编号、固定层级、行密度或运行时刻添加特判。

## 2. 输出与测量口径

| 输出 | 内容 |
| --- | --- |
| `result/DBLP/Test80/query_g13/test80_stats.txt` | 原始逐询问记录；每条新记录含 387 个 `key=value` 字段 |
| `result/DBLP/Test80/query_g13/cross_query_runner.log` | 启动、结束、截止时间与进程返回值 |
| `result/DBLP/Test80/query_g13/test80_cross_query_summary.csv` | 每个询问一行的结构、总量、剪枝、连接和阶段时间 |
| `result/DBLP/Test80/query_g13/test80_cross_query_layers.csv` | 每个询问的 D0--D6、A0--A5 分层统计 |

每个询问在独立进程中运行，因此 `peak_rss_mb` 是该询问自身的峰值。`ordinary_row_bytes` 与 `anchored_row_bytes` 按有序行向量的实际 `capacity` 统计，适合解释行存储组成；它们不是 RSS，因为 RSS 还包括图、组距离、堆和临时数组。

每个 D/A 层记录保留值、种子、堆弹出、稀疏/稠密行数、行字节、层耗时、层结束时的 `best`，以及候选合并和图传播分别被旧值、下界或接受分支接收的次数。每次下界求值还记录 `farthest`、group-tour、directed-cut 三者中的主导者。连接统计区分直接扫描、二分探测和双指针线性归并，并按实际扫描域估算工作量。A 另外记录完整化的扫描顶点数、检查数、命中数和耗时；packing 记录购买时已经完成的 D2 行数、D2 工作量和保留值数。

这些计数只依附于原有控制流做整数累加，不保存逐状态轨迹，也不参与算法决策。

## 4. 时间与空间瓶颈

### 4.1 普通状态 D 是主要空间来源

19 条询问中，有序行总字节与 peak RSS 的 Pearson 相关系数为 `1.000`。这不表示二者严格相等，而是说明不同询问的峰值差异几乎完全随行存储增长。跨询问累计的主要层如下：

| 层 | 累计耗时 | 累计保留值 | 累计行存储 |
| --- | ---: | ---: | ---: |
| D2 | `2715.7s` | `1146.7M` | `12217.7MiB` |
| D3 | `5340.0s` | `2438.2M` | `26802.2MiB` |
| D4 | `6290.1s` | `2120.2M` | `24207.8MiB` |
| D5 | `4435.3s` | `492.2M` | `5690.1MiB` |
| D6 | `4958.0s` | `299.7M` | `3465.9MiB` |
| A1 | `418.3s` | `141.8M` | `1556.8MiB` |
| A2 | `1443.1s` | `380.8M` | `4249.4MiB` |
| A3 | `3309.5s` | `724.1M` | `8168.8MiB` |
| A4 | `5413.7s` | `933.8M` | `10639.1MiB` |
| A5 | `6548.0s` | `804.6M` | `0MiB`，最终层流式消费 |

D3 与 D4 是首要空间层。D5/D6 的保留值已经明显下降，但耗时没有同比下降，说明高层连接与传播的单位保留值成本更高。A5 不落盘，却是累计耗时最大的 A 层；仅减少持久存储不能解决它的生成和完整化成本。

最重的 q25 用时 `7619.9s`，peak RSS 为 `25541.4MiB`（`24.94GiB`）。它保留 `1388.6M` 个 D 值和 `1267.2M` 个 A 值，D/A 行分别占 `14.41GiB` 与 `9.01GiB`。D 用时 `3340.8s`，A 用时 `4228.0s`，其中完整化为 `1060.8s`。q25 的 D3/D4 行分别约 `3.84GiB/5.39GiB`，A4 行约 `4.75GiB`；流式 A5 仍生成约 `430.2M` 个值。这是后续空间和最终层时间优化必须保留的压力样本。

### 4.2 D 的时间不能再视为公共小开销

D 时间在 19 条询问中的 16 条高于 A；只有 q6、q23、q25 由 A 主导。D 时间与连接工作量、保留值、下界求值数的相关系数分别为 `0.948/0.981/0.973`。A 时间与连接工作量、保留值、完整化扫描量的相关系数分别为 `0.849/0.983/0.955`。因此下一轮既要减少 D3/D4 的状态物化，也要减少 A4/A5 及完整化实际扫描；只优化其中一边不会稳定改善跨询问表现。

## 5. 上下界与有序连接

branch-junction 在 `19/19` 条询问中改善初始 incumbent，D 又在 `19/19` 条中继续改善；A 在 `18/19` 条中得到最终改进，只有 q34 没有改进 D 的 incumbent。即使 q34 没有最终更新，也不能据此跳过 A，因为当前仍需要它完成精确性证明。junction 后上界与最终最优值之比的中位数为 `1.1365`，D 后为 `1.0362`：junction 提供稳定的早期收益，D 通常把缺口压到较小，但 A 仍承担最后的精确闭合。

在实际主导下界中，D 的 `farthest/group-tour/directed-cut` 占比为 `1.23%/0.16%/98.62%`，A 中为 `8.92%/5.23%/85.85%`。directed-cut 是当前绝大多数状态的有效下界来源；group-tour 在 D 中几乎从不主导，后续可测量其求值成本并研究惰性求值，但在没有等价性和收益证据前不能直接删除。

D 合并候选中，`1.83%` 被旧值淘汰，`97.28%` 在生成后被下界淘汰；A 对应为 `4.91%/94.12%`。图传播阶段的旧值/下界淘汰占比，D 为 `68.49%/26.99%`，A 为 `62.11%/34.87%`。这说明下界本身有效，主要问题是它在候选已经由有序行连接产生之后才拒绝了绝大多数工作。

按估算扫描域汇总，D 的直接扫描、二分探测、双指针线性归并分别占连接工作量的 `35.91%/4.59%/59.50%`；A 中为 `24.15%/7.23%/68.62%`。因此主线仍应放在离线有序列表和线性归并上，优先研究如何在归并过程中利用合法下界停止或跳过区间，而不是改回 Hash，也不应先做二分路径的常数级微调。

progressive packing 在 `18/19` 条询问中被实际 D2 工作购买：16 条执行两轮，2 条执行一轮；q6 未购买。q6 的 wall 为 `588.3s`，A 占 `60.4%`，说明现有基于工作量的购买规则确实能区分不值得预处理的询问，不需要按数据集或询问编号设置开关。

稠密行只集中在低层：19 条询问累计 D2/D3/D4/D5/D6 稠密行数为 `287/459/171/1/0`，高层绝大多数为稀疏行。当前空间瓶颈来自稀疏行数量与总值数，而不是稠密阈值选错；调整阈值不是优先研究方向。

## 6. 后续研究优先级

1. **让离线有序归并在生成前感知下界。** 目标是利用 directed-cut 等合法结构，对连续候选区间给出可证明的共同下界，从而避免物化随后被淘汰的 `94%--97%` 合并候选。实现应继续保持排序行和双指针归并，不引入 Hash。
2. **缩短 D3/D4 行的生命周期或减少其精确表示。** 两层决定峰值空间。可研究按消费者流式释放、可证明的延迟构造或受控重算，但必须先列清 A+D、D+D 和完整化对每层的最后消费者，不能因 q1 或单个询问的访问模式提前删除状态。
3. **同时处理 A4/A5 与完整化。** A5 虽不存储仍耗时最大，说明重点应是少生成、少连接、少扫描，而非只压缩 row 容器。q25 应作为这一方向的压力样本。
4. **测量下界求值本身的可省成本。** directed-cut 主导稳定；group-tour 尤其在 D 中命中极少。下一探针应记录各下界独立耗时及“若延后求值是否改变最终 max”，据此判断惰性顺序，而不是直接增加或删除经验开关。
5. **后续门槛必须跨结构档位。** 日常快速门槛至少跨数据集和结构档位保留代表询问，但不能参与算法内部选择。q25 与完整 DBLP g13 q1 都属于长门，只在有突破性机制或发行节点时重跑；Test98 已用旧 q25 聚合统计先给出不依赖层内分布的空间上界。

普通图/query 压缩、经验 density threshold、二分探测微调和 junction 删除均不由本轮数据支持。普通压缩也可被 baseline 共用，不应作为本方法主线贡献。Test98 后来采用的是三种等价 row 表示的逐行精确字节最小化，不是数据拟合的 density threshold。

## 9. Directed-Cut 行证书后续验证

随后尝试把每行的最小约化代价和最小完整对偶代价组合成整次连接下界，在 D+D 或 A+D 有序连接前跳过不可能改善 incumbent 的整对行。该证书无经验参数且保持无 Hash，但 fast20 虽跳过 `68,937/35,434` 次 D/A 合并，D 状态数完全不变，总时间仍由 `9.099s` 退化到 `9.734s`；真实 Toronto g13 q1 又退化约 `19.3%`。这验证了“下界拒绝太晚”的现象，却说明**行级标量不足以减少主导物化状态**。实现和诊断字段均已撤回，未运行完整 DBLP，详见 `archive/test82_dual_row_certificate_20260714.md`。

## 10. Group-Tour 按需求值

第 5 节提出的惰性求值已完成为 Test83。新流程先计算 `max(farthest,directed-cut)`；若该下界已经拒绝候选，则不再计算 group-tour，否则恢复原三个下界的完整最大值后再决定是否接收。它不是删除弱下界，也没有经验阈值，因此保持旧 Test80 的全部状态和执行语义。

DBLP g13 q5 中，D/A 分别只有 `1.72%/1.10%` 的首次下界求值需要进入 group-tour；wall 为 `276.117s -> 249.146s`，普通阶段为 `165.665s -> 143.879s`，最优值及 D/A values、pops 全部相同。该正向机制已合入 Test80，完整说明见 `test83_lazy_tour_bound.md`。ReleaseV4 尚未更新，完整 DBLP g13 q1 未重跑。

## 11. 锚定顶层流式调度

Test84 不再等待全部 A4 行同时驻留后才启动 A5，而在某个 A5 的全部直接 A4 子集完成后立即消费，并在每个 A4 的最后一次使用后释放 payload。最终版本保留原整数 `mask` 生产者顺序；按集合元素字典序虽然把行数峰值降得更多，却在 DBLP q5 延后强 incumbent，使 A pops 增加 `73.5%`，已经否决。

DBLP g13 q5 的最终版本保持 A4 values/pops 为 `155,755/174,773`，A4 流式 payload 峰值为 `1,368,192B`，比该层累计 `1,869,060B` 低 `26.8%`；wall 为 `242.885516s`，答案仍为 `14.5867185184`。进程 peak RSS 基本不变，因为 q5 的峰值先在普通 D/公共预处理出现。正确性、复杂度、fast20 与 Toronto 证据见 `test84_anchored_top_stream.md`；Test84 当时未重跑 DBLP q1/q25，后续 q25 结果见第 14 节。

## 12. Directed-Cut 优先求值

Test87 把 Test83 的第一阶段 `max(farthest,directed-cut)` 再拆成两步：先计算 directed-cut，只有不能拒绝候选时才扫描剩余组得到 farthest，随后仍按 Test83 对幸存者计算 group-tour。各阶段都是合法且单调增强的下界；所有幸存者最终恢复旧完整下界，因此状态、队列键和答案不变。

DBLP g13 q5 中，D/A 分别只有 `1.724%/1.054%` 的首次 cut 求值继续执行 farthest；wall 为 `242.885516s -> 186.895733s`，D 为 `139.609703s -> 97.984235s`，A 为 `57.499670s -> 35.212340s`。D/A values、pops 及 completion checks 与 Test84 严格相同。fast20 和 Toronto 没有稳定加速，表明主要收益是避免大图 group-distance 工作集上的分散读取。完整说明见 `test87_cut_first_bound.md`。

后续 Test88 曾用“全组 dual 总和减去已覆盖组”构造保守补集预筛选。它随机正确且 q5 仅再快约 `0.43%`，但 fast20 退化约 `2.8%`、peak 增加约 `19.3MiB`，故源码与结果已撤回，见 `archive/test88_complement_dual_prefilter_20260715.md`。Test88 当时仍未启动 DBLP g13 q1/q25；当前 q25 长门见第 14 节。

Test89 又在原 bit 顺序内用非负 cut 前缀提前结束求和。该机制走到末尾时得到与 `dual.At` 完全相同的 double，但 q5 的 D/A 实际 term 读取仍为完整求和的 `90.10%/90.96%`，wall 反而增到 `202.975s`。因此 cut 内逐项短路也已撤回，见 `archive/test89_dual_prefix_short_circuit_20260715.md`。

## 13. 顶层 D 中的 A0 Completion

Test90 利用平衡分块的大小关系：`g` 为奇数时 A0 的两侧都是 `D_h`，`g` 为偶数时是 `D_h+D_(h-1)`，所以每个 A0 partition 都能在对应最高层 D row 完成时结算。它仍使用原有三列表有序相交，只把可行上界前移，并删除后续重复 A0 扫描。

DBLP g13 q5 中，流式 A0 以 `0.678ms` 和 `2,282` 次共同根检查把 `best` 从 `15.1140873783` 降到 `14.8708439399`，使后续 D6 values/pops 下降 `35.37%/37.99%`，wall 从 Test87 的 `186.896s` 降到 `183.914s`；A values/pops 完全不变。完整说明见 `test90_streamed_a0_completion.md`。Test91 的补集成对 mask 顺序虽改善 Toronto 单例，却在 fast20 跨库退化约 `2%`，已撤回且未运行 DBLP。

## 14. Ranked Bitmap 有序行

Test98 保持第 13 节后的全部状态与调度，只为每张已完成 D/A row 增加第三种物理布局。除原 sparse 和 dense 外，ranked bitmap 用全顶点 occupancy、每个 64-bit word 之前的 rank、紧凑距离数组，以及普通 D 行的顶点域 branch bits。每行按三种表示的精确逻辑字节数取最小，不设置数据集、`g`、层号或 density threshold。

DBLP g13 q5 的最优值仍为 `14.5867185184`，D/A values、pops 与 completion checks 均不变；wall 为 `183.914s -> 158.150s`，ordinary 为 `96.390s -> 81.354s`，anchored 为 `34.729s -> 29.702s`。completion 由 `2.141s` 增到 `2.809s`，但未抵消主阶段收益。该询问仅 D2 有 `5` 张 bitmap row，D2 payload 从 `43,560,712B` 降到 `40,100,112B`；这些低层行会被大量后续连接复用，因此时间收益大于一次性空间差值。peak RSS 为 `2134.734MiB -> 2130.301MiB`，基本不变。

Test98 后续按长门纪律重跑了 q25。当次 Test83/84/87/90/98 主线保持最优值 `12.0889822532`，query peak 从历史 Test80 的 `25541.363MiB` 降到 `18493.941MiB`，下降 `27.6%`；wall 则从 `7619.938s` 增到 `8652.038s`，回退 `13.5%`。D2--D5 与 A1--A4 状态数不变，这些层的累计 row payload 减少约 `5405.4MiB`；D6 还包含 Test90 的状态削减。由于历史对照早于 Test83--98，这不是 Test98 的单变量时间对照，但足以说明当次三布局在重查询上是显著的空间换时间。完整布局分布、阶段计时和预测边界见 `test98_ranked_bitmap_rows.md`。DBLP g13 q1 仍未重跑。

该 q25 长跑之后，Test103 已把 bitmap accumulator 与 branch bits 的有序半连接隔离为独立内核；fast20 direct work 降约三成，DBLP q5 两次通过端到端门。但 q25 没有再次运行，因此本节 `8652.038s/18493.941MiB` 仍只代表 Test98，不得写成 Test103 的实际效果。机制与边界见 `test103_out_of_line_bitmap_semijoin.md`。

## 15. q32 中等门槛与 Completion 位图接口

为避免每次结构探针都启动 q25/q1，当前新增 q32 作为约 8 分钟的 DBLP g13 中等门槛。Test103 q32 得到 `6.3393307977 / 475.287922s / 2205.238MiB`；D/A join work 相对第 3 节历史记录分别下降约 `51.0%/52.7%`，但历史版本早于 Test83--103，不能当成 Test103 单变量时间收益。q32 能覆盖 ranked-bitmap join，却没有形成 bitmap-compatible completion partition。

Test104 随后为 `A+D+D` completion 加入共享 A-root bitmap 与三路 word 相交。q32 结果为 `468.353096s/2205.371MiB`，答案、D/A states、completion scans/checks 与 Test103 逐项相同；新内核调用数为 `0`，因此这次 `-1.46%` 只作未命中路径无回退证据。真正命中新路径的 fast20 把 completion 从 `870.788ms` 降到 `472.844ms`，checks 不变。

Test104 单变量阶段没有重跑 q25。其 Test98 布局仍能严格证明覆盖范围：D3 全部 220 张为 bitmap，D4 只有 30/495 张 sparse，因此 A4 的 `D4+D4` 至少 `15,225` 个、A5 的 `D3+D4` 至少 `26,040` 个 partition 会命中 Test104，合计至少 `41,265`。后续组合版 q25 实际命中 `83,048` 个，但不能反推 Test104 的单变量时间；完整推导见 `test104_completion_bitmap_intersection.md`。

Test105–107 随后把每张现有 D/A row 的精确最小值组织为分块、共同根和普通分量三级下界。DBLP g13 q5 保持最优值与全部 D/A 状态数不变，completion scans/checks 分别由 `12,812,963/4,317,363` 降到 `6,012,094/68,989`，局部时间由 `2.9998s` 降到 `0.8870s`。q32 同样保持状态不变，scans/checks 由 `303,933,303/204,515,835` 降到 `127,289,990/3,325,161`，completion `24.60s -> 7.05s`，wall 当前观测 `468.35s -> 425.97s`。

该结构信号随后触发一次新的 q25 长门。当前 Test107 组合版保持最优值 `12.0889822532`，与 Test98 的 `121` 个 D/A 状态、布局、pops 和逐层 best 字段完全相同；completion scans/checks 由 `37.155B/32.815B` 降到 `32.598B/46.019M`，completion `1211.875s -> 488.765s`。query wall 为 `8652.038s -> 8121.863s`，peak RSS 为 `18493.941MiB -> 18498.070MiB`，即时间改善 `6.13%`、空间基本不变。当前长门同时包含 Test103 的 branch 半连接与 Test104 的位图 completion，不能把组合差异全部归因于 Test107；其单变量证据仍来自 q5、q32 和 Toronto。DBLP g13 q1 未重跑，统一说明见 `test105_completion_partition_minimum.md`。
