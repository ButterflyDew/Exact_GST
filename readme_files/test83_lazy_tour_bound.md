# Test83：按需计算 Group-Tour 下界

更新时间：2026-07-14。Test83 是合入 Test80 研究分支的一项精确求值顺序优化；它不建立新状态、不改变离线有序行连接，也不调用框架 B。ReleaseV4 目前尚未合入该机制。

## 1. 问题与结论

Test80 在普通状态 D 和锚定状态 A 的候选进入行或优先队列前，使用三个合法下界：到任一剩余组的最远距离 `F`、group-tour 下界 `T` 和 directed-cut 下界 `C`。旧实现每次首次访问行内顶点 `v` 时直接计算

```text
H(v) = max(F(v), T(v), C(v)).
```

DBLP g13 的 19 条跨询问统计显示，最终主导 D 下界的 `98.62%` 是 `C`，只有 `0.16%` 是 `T`；A 中两者分别为 `85.85%` 和 `5.23%`。因此 Test83 **不删除 `T`，而是先用便宜且合法的 `max(F,C)` 尝试拒绝候选，只在候选仍可能改善当前最优上界时才计算 `T`**。

## 2. 主线流程

对当前行、顶点 `v`、候选代价 `d` 和当前最优上界 `best`，执行以下流程：

1. 首次访问 `v` 时计算 `Hcheap(v)=max(F(v),C(v))`，并在本行缓存结果。
2. 若 `d+Hcheap(v)>best`，立即拒绝候选。此时因为 `H(v)>=Hcheap(v)`，完整下界也必然拒绝它，流程结束。
3. 否则按原算法计算 `T(v)`，得到完整下界 `H(v)=max(Hcheap(v),T(v))`，并在本行缓存结果。
4. 若 `d+H(v)>best`，拒绝候选；否则按原 Test80 逻辑写入行或优先队列。

**步骤 2 是唯一新增的提前结束位置。** 所有通过 cheap 检查的候选都在接受前恢复完整的旧下界，因此优先队列键、行值、传播顺序和停止条件保持不变。

该流程同时用于普通 D 的 seed/relax 候选和锚定 A 的 seed/relax 候选。早期上界构造、branch-junction、progressive packing、完整化以及 D+D/A+D 的离线有序归并均不改变。

## 3. 三个下界分别做什么

### 3.1 最远组距离 `F`

`F(v)` 是 `v` 到所有尚未覆盖组的最短距离最大值。任何可行补全至少要接触每个剩余组，因此其代价不小于 `F(v)`。求值只扫描剩余组的预计算距离。

### 3.2 Directed-cut 下界 `C`

`C(v)` 读取现有 dual potential 对剩余组给出的合法下界。它在 DBLP 上最常主导，而且单次读取比枚举 group-tour endpoint 更轻，因此与 `F` 一起构成第一阶段。

### 3.3 Group-tour 下界 `T`

Test80 预先对组间度量做 subset path DP。给定剩余组集合后，`T(v)` 枚举预计算的首尾组组合，将 `v` 到两个端点组的距离与组间路径相加后除以二。预处理没有变化；Test83 只减少热循环中调用 `At(v,mask)` 的次数。

## 4. 缓存与统计实现

`heuristic_stamp[v]` 仍表示缓存属于哪一行，`heuristic[v]` 保存当前值。Test80 额外使用一个每顶点 1 byte 的 `heuristic_state`，区分 cheap 下界由 `F/C` 中谁主导，以及 `T` 是否已经求值。这样同一行内多次访问同一顶点时，每个分量至多计算一次，同时继续准确维护原有下界来源统计。

这个 1-byte 状态只服务于 Test80 的研究统计。若机制进入无逐候选统计的 Release，可删除来源区分，不需要增加发行版的渐进空间。

新增字段 `d_h_tour_evals_s*` 和 `a_h_tour_evals_s*` 分别记录 D/A 各层实际调用 group-tour 的顶点数；原有 `d_h_evals_s*` 和 `a_h_evals_s*` 仍记录首次计算下界的顶点数。

## 5. 正确性

**结论：Test83 与旧 Test80 返回完全相同的最优值，并保留相同的状态和队列行为。**

首先，`F`、`C`、`T` 都是合法下界，所以 `Hcheap=max(F,C)` 和 `H=max(F,C,T)` 都合法，且 `Hcheap<=H`。若步骤 2 拒绝候选，即 `d+Hcheap>best`，必有 `d+H>best`，旧实现也会拒绝。若步骤 2 不拒绝，步骤 3 会计算完整的原 `H`，之后的接受条件和队列键与旧实现逐项相同。因此每个候选的最终去留、保存值、弹出顺序和 incumbent 更新均不改变，归纳到全部 D/A 行即可得到等价性。

实现验证与该结论一致：最终 byte-state 源码通过 seed `714252` 的随机小图 DPBF 对拍 `50/50`；此前同一求值流程又通过 seed `714231` 的 `100/100`。fast20 的 20 条答案以及普通/锚定 values、pops 四项汇总均与旧 Test80 完全一致。

## 6. 复杂度与空间

设某行首次访问 `N_H` 个顶点，其中 `N_T` 个通过 cheap 检查。旧实现在这些顶点上全部计算 tour；Test83 只计算 `N_T` 次。单次 `F/C` 成本不变，最坏情况下 `N_T=N_H`，所以最坏时间复杂度与旧 Test80 相同；实际节省取决于 `N_T/N_H`。

Test80 研究实现增加 `n+1` bytes 的状态数组，渐进空间仍为 `O(n)`，并且远小于 D3/D4 有序行。DBLP q5 的图有 `2,497,782` 个顶点，该数组约为 `2.38MiB`；若移除来源统计则无需这块独立空间。

## 7. 实测结果

所有计时均为 Release/O2。fast20 旧 Test80 为 `9.099s`；同一 Test83 byte-state 源码两次为 `8.473s/8.604s`，即降低 `6.88%/5.44%`。短套件存在系统波动，因此不以单次最好值作为主结论。

真实 Toronto g13 q1 的旧 Test80 为 `8.722s`。Test83 三次为 `8.285s/9.257s/8.296s`，中位数 `8.296s`，相对旧值降低约 `4.9%`。答案始终为 `0.7048467020`。

DBLP g13 q5 是本轮唯一完成的新长查询，也是主要性能证据：

| 指标 | 旧 Test80 | Test83 | 变化 |
| --- | ---: | ---: | ---: |
| wall | `276.117s` | `249.146s` | `-9.77%` |
| ordinary D | `165.665s` | `143.879s` | `-13.15%` |
| anchored A | `61.670s` | `59.581s` | `-3.39%` |
| completion | `1.895s` | `2.078s` | 短阶段波动 |
| peak RSS | `2129.398MiB` | `2134.648MiB` | `+5.250MiB` |
| 最优值 | `14.5867185184` | `14.5867185184` | 相同 |

q5 的普通状态只对 `6,007,837 / 348,509,194 = 1.72%` 的首次下界求值调用 tour；锚定状态为 `1,469,220 / 133,434,374 = 1.10%`。普通 values/pops 分别严格保持 `35,981,208/7,599,016`，锚定 values/pops 保持 `3,966,335/1,712,405`。因此加速来自**少算不影响决策的 tour 下界**，不是删除状态、改变有序连接或放宽剪枝。

本轮没有重跑完整 DBLP g13 q1。一次误启动的 DBLP q2 在完成前已终止，结果不计入任何表格。按照长跑纪律，完整 DBLP 只在机制进入发行候选或出现更大的结构突破后运行。

## 8. 与论文及 ReleaseV4 的关系

Test83 没有引入新的论文机制或外部引用；`F/T/C` 的来源仍见 Test80 和 ReleaseV4 文档。这里的贡献边界只是**对已有合法下界做保持等价的分阶段求值**。它没有数据集、固定 `g`、层级、密度或运行时刻特判，也不压缩输入图或查询，符合 `agent.md` 第六条。

当前代码仅合入 `methods/Test/test80_anchor_progressive.cpp` 及其统计接口。ReleaseV4 保持冻结；若后续发行，应删除研究计数器和下界来源 byte，只保留 cheap 拒绝与按需 tour 两步。

后续 Test84 在该基线上加入 A 顶层流式调度；Test83 本文的数据继续作为单独机制的冻结对照，组合版见 `test84_anchored_top_stream.md`。
