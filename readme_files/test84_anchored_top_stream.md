# Test84：锚定顶层的依赖驱动流式调度

更新时间：2026-07-15。Test84 是已经合入 Test80 研究分支的精确调度改进。它不改变 ReleaseV4 的 D/A 状态定义、转移、下界或离线有序行表示，也不使用 Hash；ReleaseV4 发行源码保持冻结。

## 1. 问题与目标

固定 permanent anchor 后，记其余组的集合为 `N`，`n=|N|=g-1`，`h=floor(g/2)`。锚定状态 `A(S,v)` 表示 anchor 与 `S subset N` 已连通，并以顶点 `v` 作为当前根。Test80 保存 `|S|<=h-2` 的行；`|S|=h-1` 是最后一层，只用于完整化和更新全局最优值，不再发布给更高层。

旧调度先完整构造并同时保存所有 `|S|=h-2` 的生产者行，再统一计算 `|S|=h-1` 的消费者。对于 `g=13`，这意味着 495 个 A4 行必须在第一个 A5 状态开始前全部存活。Test84 的目标是：**不改变任何状态内容，只利用最后两层的依赖关系，让 A5 尽早消费已经齐备的 A4 行，并在 A4 行最后一次被消费后立即释放。**

## 2. 主线流程

1. `A0` 到 `A(h-3)` 仍按原来的层序和整数 `mask` 递增顺序计算，所有低层行正常保存。
2. `A(h-2)` 仍按原来的整数 `mask` 递增顺序逐行产生。每完成一个生产者 `P`，调度器把它的所有一位扩展 `F=P union {x}` 的就绪计数加一。
3. 当某个 `|F|=h-1` 的全部 `h-1` 个直接子集都已完成时，立刻按原转移计算消费者 `A(F)`。该消费者完成完整化后不保存行。
4. 一个 A4 生产者每被一个直接超集消费一次，就减少一次剩余使用计数；计数归零时立即释放其 `vertices/distances/branch_bits` payload。
5. 全部生产者结束后，所有消费者也必然完成；调度器检查 live row 和 live bytes 均为零。

这里的“流式”只作用于最后一个需要保存的 A 层。普通 D、低层 A、离线有序列表连接、Dijkstra closure 和完整化公式都没有变化。

## 3. 为什么依赖已经足够

计算最终状态 `A(F)` 时，锚定侧可能是 `F` 的任意真子集。所有大小至多 `h-3` 的锚定行在进入流式阶段前已经完成；大小为 `h-2` 的依赖恰好是 `F` 的全部直接子集。因此，**“`F` 的 `h-1` 个直接生产者全部就绪”与“`A(F)` 所需的全部锚定依赖已经就绪”等价**。

反过来，生产者 `A(P)` 在自身完成后不会被同层生产者读取，只会被满足 `P subset F`、`|F|=h-1` 的最终消费者读取。其全部直接超集都处理完以后，后续计算不可能再次访问该行，所以释放是安全的。

## 4. 正确性结论

Test84 只是原状态依赖 DAG 的另一种拓扑序。每个 `A(S,v)` 使用相同的 seed、相同的有序同根连接、相同的路径闭包和相同的完整化操作，故候选集合没有改变。提前执行的最终消费者只可能用一棵真实可行树降低 `best`；所有基于 lower bound 的拒绝仍满足 `value+lower>best`，所以更早得到更小的可行上界不会删除最优解。

**结论：Test84 与 Test83/Test80 返回相同的精确最优值。**最终整数顺序版本通过两批独立随机 DPBF 对拍：seed `714303` 为 `100/100`，seed `714304` 为 `200/200`，范围为 `n=4..18, g=2..13`。

## 5. 为什么必须保留原生产者顺序

拓扑正确不代表剪枝工作量相同。曾测试按集合元素做字典序枚举：它把 `g=13` 的生产者峰值从 495 行降到 267 行，但也延后了旧调度中较早出现的强 incumbent。DBLP g13 q5 的 A4 values 因而从 `155,755` 膨胀到 `783,759`，总 A pops 从 `1,712,405` 增至 `2,970,854`，wall 达到 `273.907s`。该顺序已否决并撤出。

最终版本严格保留旧 Test80 的整数 `mask` 递增生产者顺序。这样，每个 A4 生产者之前看到的生产者前缀与 Test83 相同，同时插入的 A5 完整化还可能更早改善 `best`。DBLP q5 的 A4 values/pops 因此严格保持 `155,755/174,773`；代价是部分 A5 消费者比旧层序更早运行，A5 values/pops 从 `58,923/62,081` 增至 `91,815/101,101`。A5 不保存 payload，实测总收益仍为正。

## 6. 时间与空间

设生产者大小 `k=h-2`。调度器遍历每条生产者到消费者的依赖边一次，边数为

`(n-k) C(n,k) = (k+1) C(n,k+1)`。

就绪和剩余使用计数使用两个长度 `2^n` 的整数数组，不引入 Hash；它们与原有 subset row 索引同阶。状态转移次数和最坏时间复杂度不变，只增加上述线性依赖调度成本。

旧顶层 payload 峰值是全部生产者行字节之和。Test84 的 payload 峰值改为任一调度前缀之后仍未完成最后一次使用的行字节之和。若 `R(P)` 表示生产者 `P` 的最后一个消费者变为就绪时对应的生产者位置，则 live row 数精确为 `max_t |{P: P<=t<=R(P)}|`。它不超过 `C(n,k)`，但最坏渐进阶仍可能相同；因此本文只把它称为**实际空间缩减**，不宣称渐进复杂度突破。

`anchored_stream_peak_rows/bytes` 只统计流式 A4 payload，不是整个进程的 peak RSS。`anchored_stream_released_rows` 统计真正分配后又释放的非空行；空行没有 payload，所以 Toronto q1 为 494 而不是组合数 495。由于 A4/A5 已交错，`best_after_a_s4` 不再表示严格的层间屏障，逐层 values/pops/bytes 统计仍保持原含义。

## 8. 论文与发行边界

Test84 没有新增外部论文引用。其调度直接来自 Test80 状态 DAG 的生产者—消费者依赖；Test80 的 Dreyfus--Wagner、Dijkstra-Steiner、Wong dual ascent 与 PrunedDP 背景仍见 `test80_anchor_progressive.md`。当前尚未完成针对这种特定 A 顶层流式顺序的文献查重，因此不单独宣称它构成论文原创点。

该机制没有数据集、固定 `g`、密度或 wall-time 特判，也没有压缩图或查询，符合 `agent.md` 第六条。ReleaseV4 暂不更新；若进入下一发行版，应保留依赖计数和最后一次使用释放，删除研究统计字段。
